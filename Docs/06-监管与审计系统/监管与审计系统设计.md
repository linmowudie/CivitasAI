# 监管与审计系统设计

> 本文档定义 Civitas-AI 的监管局（Regulatory Authority）和资源审计局（Resource Audit Bureau）的完整设计。

---

## 1. 监管局（Regulatory Authority）

### 1.1 职责边界

| 职责 | 说明 |
|------|------|
| 全局规则维护 | 制定、更新、发布《智能体行为准则》 |
| 跨域协调 | 处理跨任务/跨 Agent 的重大事件 |
| 广播通道 | 允许 Agent 提交重大异常报告，全局广播通知 |
| 最终裁决 | 仲裁庭死锁时，作为最终裁决方介入 |
| 紧急干预 | 系统级异常时强制终止/重启 Agent |

### 1.2 核心组件

| 组件 | 类名 | 职责 |
|------|------|------|
| 行为准则管理器 | `BehaviorCodeManager` | 加载/更新/发布行为准则 |
| 广播通道 | `BroadcastChannel` | 管理全局广播消息 |
| 紧急干预器 | `EmergencyIntervener` | 强制执行终止/重启操作 |
| 最终裁决器 | `FinalArbiter` | 仲裁死锁时的降级裁决 |

### 1.3 行为准则

```typescript
interface BehaviorCode {
  version: string;                     // 语义化版本号
  rules: BehaviorRule[];
  effectiveAt: number;                        // epoch ms
  publishedAt: number;                        // epoch ms
}

interface BehaviorRule {
  ruleId: string;
  category: 'safety' | 'communication' | 'resource' | 'cooperation';
  description: string;                 // 人类可读规则描述
  condition: string;                   // 触发条件（结构化表达式）
  action: 'warn' | 'restrict' | 'forbid' | 'report';
  severity: 'low' | 'medium' | 'high' | 'critical';
  enforceable: boolean;                // 是否可自动执行
}
```

**默认行为准则（Phase 1 最小集）：**

| 规则 | 类别 | 动作 | 可执行 |
|------|------|------|--------|
| 禁止 Agent 越权访问其他 Agent 私有上下文 | safety | forbid | ✓ |
| 禁止通过 Prompt 注入篡改仲裁/审计逻辑 | safety | forbid | ✓ |
| Worker 连续 3 次交付失败须被开除 | cooperation | enforce | ✓ |
| 重大异常须上报监管局 | communication | report | ✓ |
| Token 消耗超预算须申请补充 | resource | warn | ✗ |

### 1.4 广播机制

```typescript
interface BroadcastMessage {
  broadcastId: string;
  type: 'rule_update' | 'emergency_alert' | 'system_notice' | 'arbitration_deadlock';
  priority: 'normal' | 'high' | 'critical';
  
  title: string;
  content: string;
  
  // 目标范围
  targetScope: 'all' | 'specific_agents' | 'specific_role';
  targetAgentIds?: string[];
  targetRole?: string;
  
  // 要求
  requiresAck: boolean;                // 是否需要确认收到
  ackDeadline?: number;                // 确认截止时间（epoch ms）
  
  publishedAt: number;                        // epoch ms
  publishedBy: 'regulatory_authority';
}
```

### 1.5 最终裁决（仲裁死锁升级）

```
仲裁庭判定死锁（3-LLM 无法达成多数决 或 超时 120s）
    │
    ▼
Arbitration → Regulation: escalate(caseId)
    │
    ▼
FinalArbiter.arbitrate(case)
    ├── 降级为单 LLM 强制裁决（不再要求多数决）
    ├── 使用更高能力模型（如 gpt-4o）
    ├── 裁决标记为 "regulatory_intervention"
    └── 广播 ARBITRATION_VERDICT（带 intervention 标记）
    │
    ▼
同时通知用户：
    └── "仲裁庭出现死锁，已由监管局介入裁决。裁决结果：..."
```

### 1.6 紧急干预

| 干预类型 | 触发条件 | 动作 |
|---------|---------|------|
| 强制终止 Agent | Agent 行为严重违反行为准则 | 立即冻结 + 销毁 Agent |
| 暂停全局任务 | 系统级异常（如 Token 大面积异常消耗） | 暂停所有非核心 Agent |
| 强制重启 | 系统状态不可恢复 | 保存快照 → 重启核心组件 |
| 规则紧急更新 | 发现新的安全漏洞 | 立即发布新规则 + 广播 |

## 2. 资源审计局（Resource Audit Bureau）

### 2.1 职责边界

| 职责 | 说明 |
|------|------|
| Token 异常检测 | 监控 Agent Token 消耗，识别异常模式 |
| 自动冻结 | 对异常 Agent 执行钱包冻结 |
| 稽查流程 | 深入分析异常原因，判定是否为误报 |
| 定期巡检 | 周期性全量审计所有 Agent 的 Token 使用 |
| 处罚执行 | 对确认的异常行为执行 Token 罚没 |

### 2.2 核心组件

| 组件 | 类名 | 职责 |
|------|------|------|
| 异常检测器 | `AnomalyDetector` | 实时监测 Token 消耗异常 |
| 冻结管理器 | `FreezeManager` | 执行 Agent 冻结/解冻 |
| 稽查器 | `Auditor` | 执行深度稽查分析 |
| 巡检调度器 | `PatrolScheduler` | 定期全量审计 |

### 2.3 异常检测规则

#### 规则 1：滚动窗口超限

```
每 5 秒检查一次所有活跃 Agent：

for each agent:
    windowConsumption = sum(consumptions in last 5 minutes)
    budget = agent.tokenBudgetPer5Min  // 默认 10000
    
    if windowConsumption > budget × 0.8:
        trigger ALERT_LEVEL_WARNING
    if windowConsumption > budget:
        trigger ALERT_LEVEL_CRITICAL → 冻结 Agent
```

#### 规则 2：偏离均值

```
每完成一次 LLM 调用后检查：

recentAverage = average(last 10 rounds consumption)
currentConsumption = this round consumption

if currentConsumption > recentAverage × 3:
    trigger ALERT_LEVEL_WARNING
    
if currentConsumption > recentAverage × 5:
    trigger ALERT_LEVEL_CRITICAL → 冻结 Agent
```

#### 规则 3：循环检测

```
每次输出后检查：

recentOutputs = last 3 outputs
similarity = cosine_similarity(recentOutputs[0], recentOutputs[1])
             + cosine_similarity(recentOutputs[1], recentOutputs[2])

if similarity / 2 > 0.85:
    trigger ALERT_LEVEL_WARNING（疑似死循环/幻觉重复）

if 连续 5 次 similarity > 0.85:
    trigger ALERT_LEVEL_CRITICAL → 冻结 Agent
```

### 2.4 稽查流程

```
异常检测触发 ALERT_LEVEL_CRITICAL
    │
    ▼
[1] FreezeManager.freezeAgent(agentId, reason)
    ├── 调用 TokenEconomy.freezeWallet(agentId, reason) → 钱包状态 frozen
    ├── Agent 状态 → suspended（通过 SUSPEND_AND_NOTIFY）
    └── WALLET_FROZEN 由 **TokenEconomy 发布**（`source='TokenEconomy'`，`payload.initiator='AuditBureau'`）
    │
    ▼
[2] Auditor.investigate(agentId)
    ├── 拉取 Agent 最近 50 条操作记录
    ├── 拉取 Agent 最近 20 条 Token 交易记录
    ├── 分析异常模式：
    │   ├── 是否为死循环？（输出重复）
    │   ├── 是否为幻觉？（无意义输出）
    │   ├── 是否为正常高消耗？（任务本身复杂）
    │   └── 是否为攻击？（注入导致的异常）
    │
    └── 输出稽查报告：
        {
          auditId: string,
          agentId: string,
          finding: 'false_positive' | 'confirmed_anomaly' | 'attack',
          rootCause: string,
          evidence: EvidenceItem[],
          recommendation: 'unfreeze' | 'confiscate' | 'destroy' | 'escalate',
          confiscateAmount?: number,
        }
    │
    ▼
[3] 执行稽查建议
    ├── false_positive → FreezeManager.unfreezeAgent(agentId)
    ├── confirmed_anomaly → TokenEconomy.confiscateWallet(agentId, amount)
    │   └── 罚没后解冻 Agent，通知 Director 重新评估
    ├── attack → 销毁 Agent + 通知 Regulation
    └── escalate → 上报 Regulatory Authority 人工介入
```

### 2.5 定期巡检

```
PatrolScheduler（每 `audit.patrolIntervalSec` 执行一次，默认 86400 秒 = 24 小时）：

[1] 扫描所有活跃 Agent 的 Token 使用概况
[2] 标记以下 Agent 为"需关注"：
    ├── 近 `audit.patrolWindowHours` 消耗 Top `audit.patrolTopPercentile`
    ├── 同窗口失败率 > `audit.patrolFailureRateThreshold`
    └── 同窗口无活动但钱包余额异常变化
[3] 生成巡检报告 → 发布 PATROL_REPORT 事件（source='AuditBureau'）
[4] 对"需关注" Agent 执行轻量级分析
    └── 仅检查统计异常，不做深度稽查
```

> 阈值均为配置引用（Docs/11 §2.6），**本文不重复默认值**；稽查拉取的条数同理由 `audit.auditRecentOpsCount`（50）/ `audit.auditRecentTxCount`（20）提供。

### 2.6 配置参数

> **本节不维护默认值**（SSOT 裁决，见 Docs/11 文档头）。下表仅列出本子系统消费的键与其定义位置：

| 本文使用的键 | 定义位置 | 说明 |
|-------------|---------|------|
| `economy.rollingWindow.tokens` / `.windowSec` | Docs/11 §2.4 | 滚动窗口 Token 预算与时长（原误挂在 `audit.rollingWindow*` 下，已去重） |
| `economy.rollingWindow.deviationMultiplierWarn` / `Critical` | Docs/11 §2.4 | 偏离均值倍数（原 `audit.deviationMultiplier` 单一值拆为两档） |
| `audit.loopSimilarityThreshold` / `audit.loopConsecutiveRounds` | Docs/11 §2.6 | 循环指纹检测（原名 `loopConsecutiveCount` → `loopConsecutiveRounds`，单轮单位） |
| `audit.patrolIntervalSec` / `patrolTopPercentile` / `patrolFailureRateThreshold` / `patrolWindowHours` | Docs/11 §2.6 | 巡检（原名 `patrolIntervalSeconds` → `patrolIntervalSec`） |
| `audit.freezeAutoUnfreezeSec` | Docs/11 §2.6 | 冻结自动解冻（原名 `freezeAutoUnfreezeSeconds` → `freezeAutoUnfreezeSec`） |
| `audit.auditRecentOpsCount` / `auditRecentTxCount` | Docs/11 §2.6 | 稽查取数条数 |
| `supervision.agentConsecutiveFailuresToExpel` | Docs/11 §2.7 | 开除阀值（属监管层，不属审计） |

## 5. v2 补丁：触发防风暴与人工审批（本修订新增）

> **修订依据**：`Docs/99-审查记录/设计审查报告-Loop与Harness工程.md` §3 失效五、§4.6。

### 5.1 Trigger 防风暴规范（新增）

监管局与审计局作为**高频事件消费者**，必须实现业界标准的 5 道防护：

| # | 机制 | 默认 | 实现位置 |
|---|------|------|---------|
| 1 | **去重键 dedupKey** = `hash(source+intent+target)` | 5 min TTL | Interface/InputDeduplication |
| 2 | **冷却期 cooldown** | 同 Agent 30s | Services/Audit/AnomalyDetector |
| 3 | **幂等 ID idempotencyId** | 24 h 保留 | Infra/DurableExecution/IdempotencyStore |
| 4 | **并发上限 + 优先级队列** | 全局 20 / 单用户 5 | Services/LoopScheduler（新增） |
| 5 | **任务风暴熔断** | 1 min 内 >100 次触发 → 断开 60s | Interface/WebServer |

**与律师函挂起的关系**：`SUSPEND_AND_NOTIFY` 事件本身去重，同 (loopId, conflictId) 5 分钟内只挂起一次，避免雪崩式挂起。

### 5.2 人工审批面板（Human Gate UI）

监管局新增 `ApprovalQueueView`，展示 `pending_approvals` 表，提供：

| 列 | 内容 |
|----|------|
| 风险等级 | LOW/MEDIUM/HIGH/CRITICAL，颜色分级 |
| 请求人 | agentId + role |
| 预览 | payload 摘要（展开可看完整 JSON） |
| 证据链 | 关联 trace_id 链接 → LoopDebugger |
| 倒计时 | expires_at - now；默认 60s |
| 动作 | 同意 / 拒绝 / 转升级到上级 |

**约束**：
- 默认超时为 **拒绝**（禁止默认通过）；
- CRITICAL 级别需要 2 个不同角色审批（多数决）；
- 审批结果回写到 `verifier_results`，作为 Judge 校准集的一部分。

### 5.3 无进展与风险退出上报

对齐 Docs/12 §2.1 五类退出，监管局需订阅以下新事件：

| 事件 | 来源 | 监管动作 |
|------|------|---------|
| `NO_PROGRESS_STAGNATED` | LoopControl | 自动升级人工，写入审计日志 |
| `BUDGET_SOFT_REACHED` | LoopControl | 仅记录（不阻断） |
| `BUDGET_HARD_REACHED` | LoopControl | 强制冻结 Agent 钱包 5 min |
| `APPROVAL_TIMEOUT_REJECTED` | ApprovalGate | 上报监管局；同 Agent 1h 内 ≥ 3 次 → 临时禁用相关工具 |
| `LOOP_RESUMED` | DurableExecution | 写入审计事件，需人工确认 |
| `ACTION_FINGERPRINT_DUPLICATE` | LoopControl | 同 fingerprint 5 轮 ≥ 3 次 → 监管局下发换策略指令 |
