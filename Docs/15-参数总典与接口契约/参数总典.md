# 参数总典（开发速查）

> **本文定位**：全系统 **参数、单位、枚举、映射、契约** 的**唯一速查入口**。开发时先查本文定位"某个值在哪、叫什么、什么类型、谁消费"，再跳到对应事实源看完整上下文。
>
> **本文不是事实源**。所有数值以「定义位置」列指向的文件为准；本文与事实源冲突时，**以事实源为准并立即回修本文**。
>
> **上游四层事实源（SSOT）**：
>
> | 层 | 唯一事实源 | 管辖范围 |
> |----|-----------|---------|
> | 配置键 + 默认值 | `Docs/11 §1.1 / §2.1–§2.11` | 全部 `Configs/*.json` 的键名与默认值 |
> | DDL | `Docs/10 §1.1 / §2–§4 / §8.2` | 全部库表、列名、列类型、约束 |
> | 事件名 | `Docs/07 §4.3` | `EventType` 枚举全集（禁止自由字符串） |
> | 类型 schema 语义 | `Docs/12`（Loop）· `Docs/13`（Durable）· `Docs/02`（架构/契约） | 接口字段语义与判定规则 |
>
> **禁止行为**：在任何其他设计文档内联配置默认值、`CREATE TABLE`、或自写新事件字符串。

> **生效状态口径（2026-09-22 校准新增）**：§2 各参数表统一增列 **「生效」**，取值只有两个：
>
> | 标记 | 含义 |
> |------|------|
> | **✅ 运行期消费** | 键值经 `Configs/*.json → Infra/Config/configLoader.ts → Src/main.ts` 的 `getConfigValue*()` 注入运行期，**改 JSON 即生效** |
> | **⚠️ 未接线** | 改 JSON **不生效**。两种子情形：**a) 零引用** —— 键在 `Src/` 无任何字面量引用（纯设计态）；**b) 常量遮蔽** —— 运行期只用模块内 `DEFAULT_*` 常量或 `?? 字面量` 兜底，`Configs` 值从未注入（值当前与默认一致，故行为看不出差异） |
>
> **对账基数**：`configLoader.ts:87-92` 实际加载 **12** 个 JSON（`default.json` + 11 个），合计 **204** 个叶子键，其中 **104 键（51%）** 在 `Src/` 无任何字面量引用（`hardLimits.*`、`verifier.*`、`context.*`、`retention.*`、`supervision.* trigger/storm`、`durable.checkpoint/metrics`、`reasoningSandwich.*` **全部**）。
>
> **根因一句话**：`getConfigValue*()` 的调用点**只存在于 `Src/main.ts`**（13 处，见 §5.4 注），其余模块各自持有 `DEFAULT_CONFIG` 字面量——这是 §2 大面积 ⚠️ 的唯一来源。目标态（Docs/11 登记的键全集）**全部保留**，仅加状态标注。

## 0. 五层参数地图（自底向上）

按此顺序实现与查参，**下层不得依赖上层参数**（对齐 skill 五层单向依赖）。

| 层 | 目录 | 参数域 | 主要事实源 | 本文档节 |
|----|------|--------|-----------|---------|
| **L1 Infra** | `Infra/` | 数据库、LLM Provider、文件、配置加载、持久执行 | Docs/10、Docs/11 §2.1/§2.2/§2.9、Docs/13 | §2.1 §2.2 §2.3 §2.9 §3 |
| **L2 Tools** | `Tools/` | 工具契约（dangerLevel / idempotency / reversibility / 沙箱 / 限流） | Docs/11 §6 | §4.1 §4.6 |
| **L3 Services** | `Services/` | 上下文装配、共享记忆、Token 经济、仲裁、审计、监管 | Docs/07、Docs/11 §2.4–§2.7/§2.11、Docs/04–§06 | §2.4 §2.5 §2.6 §2.7 §2.11 |
| **L4 Core** | `Core/` | 主循环、StopRules、Verifier、LoopState、编排路由 | Docs/12、Docs/02、Docs/03、Docs/11 §2.3/§2.8 | §2.3 §2.8 §4 §5 |
| **L5 Interface** | `Client/`、`Interface/` | 服务端口、WS 协议、推送节流、审批面板 | Docs/08、Docs/09、Docs/11 §2.1 | §2.1(ui) §4.5 |

**跨层红线（三条）**：
1. **单位/标度不得跨层变形**：比例只在 L5 展示层 ×100，其余层恒 0.0–1.0；时间戳全链路 epoch ms。
2. **参数不得跨层复制**：L3–L5 需要 L1 的值时**引用配置键名**，不写数值。
3. **ID 语义不得跨层混用**：`session_key` / `trace_id` / `operation_id` / `loop_id` 粒度固定（§6）。

## 1. 命名与单位规范

### 1.1 六条强制规则

| # | 对象 | 规则 | 正例 | 反例（v2.1 已清） |
|---|------|------|------|------------------|
| N1 | 配置文件键 | **camelCase** | `httpPort`、`qualityThreshold` | `max_consecutive_failures` |
| N2 | DB 表名/列名 | **snake_case**，与 TS 字段**机械转换** | `budget_used_tokens` | `timeoutMs` 对应列写成 `t_out` |
| N3 | TS 接口字段 | **camelCase**（`LoopConfig` 除外，见 X2） | `budgetUsedTokens` | — |
| N4 | 时长 | 键名**必带单位后缀**，数值不带单位 | `busyTimeoutMs: 5000`、`approvalTimeoutSec: 60`、`loopConsecutiveRounds: 5` | `timeout: 5000`、`monitoringInterval: "60s"` |
| N5 | 比例 / 评分 | 一律 **0.0–1.0** 浮点；DB 列 `REAL` | `qualityScore: 0.85` | `quality_score INTEGER /* 0-100 */` |
| N6 | 时间戳 | TS `number`（**epoch 毫秒**）+ `_at` 后缀；DB 列一律 `INTEGER` | `recordedAt` / `recorded_at` | ISO-8601 `TEXT` |

其他后缀：金额 `_usd`（REAL）· JSON 列 `_json` 结尾 · 布尔列 `is_*` / `*_enabled`（INTEGER 0/1）· 计数 `*Count` · 上限 `*Ceiling` · 倍率 `*Multiplier` / `*Factor`。

### 1.2 命名豁免清单（穷举，新增须先登记 Docs/11 §1.2.1）

| # | 豁免对象 | 风格 | 理由 | 边界（超出即违规） |
|---|---------|------|------|------------------|
| **X1** | `modelRouter.json` 的 `providers[]` / `models[]` **内层键** | snake_case：`base_url` `api_key_ref` `display_name` `context_window` `max_output` `supports_vision` `supports_tools` `cost_per_1k_input` `cost_per_1k_output` | 上游 OpenAI / Anthropic 兼容契约 | 仅内层；`routing` 段与 `reasoningSandwich` 段仍 camelCase；`Infra/Llm` 边界层负责转成 camelCase 领域对象（如 `ModelPricing.costPer1kInput`）。⚠️ `display_name`（`modelRouter.json:7`）**已在代码中使用但未登记** Docs/11 §1.2.1（2026-09-22 校准：待补登记） |
| **X2** | `loopConfig.json` 的 `loopDefaults` / `roleOverrides[*]` **内层键** ＋ TS `LoopConfig` 接口字段 | snake_case：`model` `max_iterations` `timeout_ms` `temperature` `token_budget` `stream` | skill `source-code.md`「LoopConfig 字段清单（强制）」，benchmark 数据集与 prompt frontmatter 复用同名 | 同名字段**不改名、不分层转换**；`hardLimits` / `stopRules` / `verifier` / `fingerprint` / `goalReanchor` / `failureFeedback` / `context` / `efficiency` 为本项目新增段，**仍 camelCase** |
| **X3** | 安全类枚举 | SCREAMING_SNAKE：`SAFE\|CONTROLLED\|DANGEROUS\|FORBIDDEN` · `LOW\|MEDIUM\|HIGH\|CRITICAL` · `PENDING\|APPROVED\|REJECTED\|TIMEOUT` · `REVERSIBLE\|PARTIAL\|IRREVERSIBLE` · `YES\|NO\|CONDITIONAL` | skill `security.md` 威胁分级，已在全局契约广泛引用 | **不得新增第四个大写枚举族**；其余枚举一律 lower snake_case |

> **枚举三处同形原则**：同一枚举在 **TS 联合类型 / DB 列存值 / 配置文件字面量** 三处必须逐字符相同，不做大小写化转换。违反即视为缺陷（v2.1 已修 `phase`、`status`、`risk_level`）。
