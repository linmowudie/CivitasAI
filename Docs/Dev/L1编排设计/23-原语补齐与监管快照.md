## P2 · `GoalEvaluator`（纯判定原语）

### 定位

| 是 | 不是 |
|---|---|
| **纯判定**：Goal 是否达成 / 是否需要重锚 | 执行件（**不声明三集合**） |
| 无状态、无副作用 | 决策者（只给 `suggestion`，状态归 C1） |
| 可被任意层调用（含 P&E 的 plan 半、Workflow 每个节点） | 约束件本身（约束件 = GoalEvaluator + 插入位置） |

### 接口

```python
@dataclass
class GoalVerdict:
    satisfied: bool
    gaps: list[Gap]                       # 未达成时：差什么
    suggestion: Literal['running', 'terminate', 'degrade']
    needs_reanchor: bool                  # 压缩后是否必须重锚（既有机制）

class GoalEvaluator:
    def evaluate(self, goal: Goal, produced: dict, immutable_zone_digest: str) -> GoalVerdict: ...
```

**两条硬约束**：
1. **不持有状态**（无实例状态；同一个 Goal + 同一 produced 必得同一结论 —— 可复算）
2. **不改状态**（`suggestion` 只是建议；状态转移归 C1）

### 反例

| # | 反例 | 期望 |
|---|---|---|
| 1 | 自己执行动作（调工具）来"验证"目标 | 拒绝（原语不执行动作） |
| 2 | 把 `suggestion` 直接写成状态转移 | 拒绝（状态归 C1） |
| 3 | 未声明判定口径（无法判定达成） | 拒绝（闭包判据，[03](03-组装检查树.md) §6） |
| 4 | 同一输入两次调用得到不同结论（暗含状态） | 拒绝（必须可复算） |
| 5 | 忽略 `immutable_zone_digest`（不可变区被改也算达成） | 拒绝 |

### 与现状

| 需要 | 现状 | 需做 |
|---|---|---|
| 目标判定 | ⚠️ 有 StopRules 的部分判定 + `goalReanchor` 重锚 | **抽取为纯判定原语**（不改行为，先同形化） |
| 不可变区 | ✅ 有（Goal 不可变区 + digest） | 复用 |

## P3 · `NodeRunner`（节点运行器）

### 定位

运行**一个节点体**（= 任意执行件），负责四件事，**不做状态决策**：

```
① 派生 loopId（外层 L → 节点 L/N1）
② 注入 grants（工具/插件/可见面/合法集）
③ 调 body.step(input)，收集 StepOutcome
④ 上报事件与计量（带自身 scope）
```

### 接口

```python
class NodeRunner:
    async def run_node(self, node: WorkflowNode, parent_scope: LoopScope,
                       parent_grants: Grants) -> Result[NodeOutcome]:
        scope = derive_scope(parent_scope, node.id)          # **唯一派生点**
        grants = narrow_grants(parent_grants, node.declared)  # 只能收紧
        body = node.body
        inp = ReactInput(state=self.deps.state_of(node),   # 由 C1 提供
                         control=self.deps.control_of(node),
                         observation=await self.deps.contexts.assemble(grants.visible, scope),
                         grants=grants)
        return await body.step(inp)
```

**唯一派生点**：`loopId` 只在 `NodeRunner` 派生（不在 `ReActLoop` 里再派），否则同一节点会出现两个 loopId，
中间件归属过滤（P0-2 防跨 Loop 污染）会失效。

### 反例

| # | 反例 | 期望 |
|---|---|---|
| 1 | 节点体内联**专用逻辑**（不是执行件） | 拒绝（破坏递归性） |
| 2 | 节点派生**第二个** `loopId`（与父给的冲突） | 拒绝（唯一派生点） |
| 3 | `grants` 被**放宽**（超出父给的范围） | 拒绝（只能收紧） |
| 4 | 节点自己决定状态（不经 C1） | 拒绝（§16） |
| 5 | 节点结束**不解绑**订阅/定时器 | 拒绝（泄漏；见 [15](15-ReActLoop原语.md) R1/R6） |

### 与现状

| 需要 | 现状 | 需做 |
|---|---|---|
| 节点运行器 | ❌ 无（有 `subtaskDispatcher`，但它派的是**子任务/子 agent**，不是执行件） | 新建 |
| loopId 派生 | ⚠️ 现无嵌套概念 | 新建（唯一派生点） |
| grants 收紧 | ⚠️ 有角色可见性（`getVisibleTools`） | 复用 + 补"收紧"语义 |

## S2 · 组件级监管快照（**监管可见性的落点**）

### 定位：**只读投影**，不是第三个快照

```
C1 落盘：组件状态快照（ckpt:component:*）
C5 落盘：会话/组装快照（ckpt:conversation:*）
S2     ：**不独立落盘** —— 它是上两者的**只读投影**（避免出现第三个写者）
```

> 见 [20-归属复核](20-归属复核.md) §2 问题 1：快照有双写者时，问题是"同一 key 空间多人写"。
> S2 **不引入第三个写者** —— 它是投影。

### 内容（**严格两项**）

| 内容 | 取自 | 说明 |
|---|---|---|
| **上下文快照** | C4 的**当前可见范围**（不是全量） | 监管要能**复现判断** |
| **工作状态** | C2/C3 账本 · C1 决策历史 · 诊断信号 | 子代收敛情况、为何选了那个状态 |

**明确不含**：**私有推理（S-01 草稿）**。
理由（[13](13-ReAct跨切面约束.md) §12.1）：**监管需要能复现判断，不需要窥探草稿** —— 后者会让监管成为另一种污染源。

### 权限边界

| 动作 | 允许 |
|---|---|
| 观察（读 S2） | ✅ 只读，无副作用 |
| 干预（拦截/降级/冻结） | ✅ 结果**经合法集收束**（见 [16](16-LifecycleController.md) §3） |
| **改写**（改组件内部数据/推理） | ❌ 只能**留痕并要求组件重决** |

### 反例

| # | 反例 | 期望 |
|---|---|---|
| 1 | 快照导出**全量上下文**（超出组件可见范围） | 拒绝（越权可见） |
| 2 | 快照**包含私有推理**（S-01 草稿） | 拒绝（监管不该窥探草稿） |
| 3 | 快照**独立落盘**（成为第三个写者） | 拒绝（只做投影） |
| 4 | 允许监管**直接改写**组件内部数据 | 拒绝（只能留痕 + 要求重决） |
| 5 | 快照含**治理内部状态**（层级隔离被打破） | 拒绝 |
| 6 | 监管干预**未走合法集**（直接置状态） | 拒绝（必须经 C1 收束） |

### 与现状

| 需要 | 现状 | 需做 |
|---|---|---|
| 诊断快照 | ⚠️ 有 `agentRegistry` 的**诊断快照** | 复用为 S2 的工作状态来源 |
| 组件级状态（账本/决策历史） | ❌ 无落点 | 新建（随 C1/C5 分区落盘） |
| 监管指令→合法集收束通道 | ❌ 无 | 新建（[16](16-LifecycleController.md) §3 已定义，需实现） |
