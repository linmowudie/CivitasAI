## 2. 发现的**三个问题**（复核的直接产出）

### 🔴 问题 1：快照有**两个写者**（C1 与 C5）

```
C1 落盘：组件挂起快照（状态/账本/决策缓存/违规记录）
C5 落盘：组装体 + 域账本 + 对话级状态
→ 同一 CheckpointPort，两个写者
```

**处置（当场定）**：**按 key 空间分区**，同一端口不同命名空间，且**各自只写自己的**：

| 写者 | key 前缀 | 内容 |
|---|---|---|
| C1 | `ckpt:component:<componentId>` | 该组件的状态/决策缓存/违规记录 |
| C5 | `ckpt:conversation:<dialogueId>` | 组装体/域账本/对话级状态 |
| C2/C3 | 随 C5 的 conversation 命名空间 | 账本**不单独落盘**（避免三方竞争） |

**判据**：**一个 key 空间只有一个写者**；跨空间读取允许（C5 恢复时读组件空间）。

> ✅ **问题 1 已落地（S4，2026-10-15）**：`Src/Core/Durable/checkpointRouter.ts` 强制"一个 key 空间只有一个写者"，C1 → `ckpt:component:*`、C5 → `ckpt:conversation:*`，DB 后端复用既有 `checkpointStore`。实现与变异检验见 [25](25-实现顺序与最小落地切分.md) §7.13。

### 🟡 问题 2：C1 读账本的**范围**必须写死

```
C1 需要：ChildRegistry（下级 join）→ 算合法集
C1 不得：DomainLedger（兄弟）→ 兄弟不影响组件级 terminate
```

若 C1 读了域账本，"父不等兄弟"立刻失效——**这正是两本账合并的翻版**。
**处置**：C1 的依赖里**只注入 ChildRegistry**，DomainLedger **不注入**（构造上不可见，而非靠自觉）。

> ✅ **问题 2 已结构化满足（S5，2026-10-15）**：`ChildRegistry` 与 `DomainLedger` 是**两个独立类**，前者供 C1 使用、后者归外层；C1 的依赖里**根本不注入** DomainLedger ⇒ 靠构造上不可见，不靠自觉。见 [17-账本-子代与兄弟](17-账本-子代与兄弟.md) §0.1 与 [25](25-实现顺序与最小落地切分.md) §7.15。

### 🟡 问题 3：`needs_decision` 的"不丢弃"由谁保证

矩阵里 C5 负责处理，但"**如何证明没丢**"没写。
**处置**：`needs_decision ≡ LifecycleEvent − {component.entered}`（§17.2 的引用式闭集），
故 C5 可以做**集合覆盖校验**：收到的项必须被处理，且事件集合是闭集 ⇒ 可机检。

## 4. 结论

- **状态/控制项**：**每项恰好一个主人**（矩阵 17 行全部 ✅）
- **三处隐患已当场处置**，其中两处（快照双写者、C1 读域账本）若不处理，会在实现时表现为"能跑但偶尔错" —— 最难查的那类
- **多生产者项**（事件）不改判据：**多生产者 + 单一总线**不算双主

**下一步**：C6 `Assembler` · C7 `AssemblyValidator` · S1 `ExecutableRegistry`（组装闭环），随后 E2/E3/E4（模式）。

## 附 · 本页结论如何被证伪

本页的"每项恰好一个主人"是**可机检**的，不是靠读：

```
检出多主：同一份表里同一项被两处标为「持有」 ⇒ 报「归属多主」
检出空缺：归属项在全部模块中无人声明 ⇒ 报「归属空缺」
```

对应的检查脚本形式：对每个归属项做「持有者计数」，**计数 ≠ 1 即失败**。
