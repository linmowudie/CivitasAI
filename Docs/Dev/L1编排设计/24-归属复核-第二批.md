## 3. 查出的三个问题与处置

### 🔴 问题 1：组装体**没记录它依赖的版本**

```
组装体依赖两个可升级的外部物：① 判据集（37 条） ② 执行件目录
若两者升级而组装体不记录版本 → 存量组装体会"悄悄失效"（同一份组装体，昨天合规今天不合规）
```

**处置（当场定）**：**组装体记录两个版本号**，且升级后必须**重验存量组装体**。

| 字段 | 含义 |
|---|---|
| `criteria_version` | 提交时所用判据集版本 |
| `registry_version` | 提交时所用执行件目录版本 |

**规则**：① 版本不匹配 ⇒ **拒绝恢复该组装体**（不得"先跑起来再说"）；② 判据/目录升级后，存量组装体进入**待重验**状态。

### 🔴 问题 2：`loopId` 有两个潜在派生者

```
NodeRunner（外层侧） 说它派生
ReActLoop R3 契约    也写了"loopId 派生"
→ 两处派生 = 同一节点两个 loopId ⇒ 中间件归属过滤（P0-2 防跨 Loop 污染）失效
```

**处置**：**派生权只在 `NodeRunner`**；`ReActLoop` **只接收** `LoopScope`（不派生、不改）。
需回填到 [15](15-ReActLoop原语.md) 的 R3。

### 🟡 问题 3：`gaps` 有两个来源，合并规则未定

```
来源 A：plan 半的 PlanOutput.gaps（资料缺口）
来源 B：GoalGuard 的 GoalVerdict.gaps（目标缺口）
```

若后写覆盖前写，**资料缺口会被目标缺口吞掉**（反之亦然）⇒ 下游看到的 `gaps` 不完整。

**处置**：**按 key 汇聚，不覆盖，保留来源标记**：

```python
def merge_gaps(*sources) -> list[Gap]:
    by_key = {}
    for src in sources:
        for g in src:
            by_key.setdefault(g.key, []).append(g)     # 同 key 保留多来源
    return [Gap(key=k, occurrences=v) for k, v in by_key.items()]
```

**判据**：`gaps` 是**单调累积**的（只增不减），直到出口；出口处必须完整输出（否则"资料不全"被隐式隐瞒）。

## 5. 结论

- **新增 6 个持有者，全部单主**（矩阵 10 行 ✅）
- 查出 **2 处 🔴 + 1 处 🟡**，均为"能跑但事后难查"的类型：
  **版本漂移**（组装体悄悄失效）、**双派生点**（归属过滤失效）、**gaps 覆盖**（缺口被隐瞒）
- 三次复核（[20](20-归属复核.md) + 本页）累计处置 **6 处隐患**，全部落在"**谁持有 / 谁派生 / 谁记录版本**"这三类上

## 附 · 本页结论如何被证伪

本页的"每项恰好一个主人"是**可机检**的，不是靠读：

```
检出多主：同一份表里同一项被两处标为「持有」 ⇒ 报「归属多主」
检出空缺：归属项在全部模块中无人声明 ⇒ 报「归属空缺」
```

对应的检查脚本形式：对每个归属项做「持有者计数」，**计数 ≠ 1 即失败**。
