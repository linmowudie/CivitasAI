## 二、五台内置管理策略机（§1.6 多级流水线 → §5.1 策略选择器）

| id | 类别 | 适用层级 | 调 LLM | 职责 | priority |
|---|---|---|---|---|---|
| `rule-micro-prune` | rule | micro / auto / manual / emergency | 否 | 裁剪旧工具结果、去重文件读取、清除 Base64 大块 | 10 |
| `subtask-isolation` | isolation | micro / auto / manual | 否 | 已关闭子任务片段整体折叠（§4.7-5） | 20 |
| `memory-flush` | flush | auto / manual / emergency | 否 | 动手前把关键信息落盘 GlobalWorkspace（§2.6-4） | 30 |
| `structured-summary` | llm | auto / manual / emergency | **是** | 旧段 → 目标/进度/约束/已尝试/剩余工作 结构化摘要 | 50 |
| `emergency-truncate` | fallback | emergency | 否 | API 溢出后的强制硬裁剪（配对保护，不留孤儿子结果） | 90 |

执行顺序由 `priority` 决定，**先免费后 LLM**；单台失败只 fail-soft 跳过，不影响其余策略机，更不阻断迭代。

**扩展方式**（「支持多种管理策略机」的落地入口）：

```ts
registerStrategy({
  id: 'my-strategy', kind: 'rule', layers: ['auto'], priority: 15, usesLlm: false,
  applies: (ctx) => /* 是否适用 */,
  execute: async (ctx) => ({ changed, messages, droppedEntryTypes, note }),
});
```

## 三、与既有监管层的关系（**不移除、不替换、只接上**）

`Src/Services/Supervision/` 六个监管函数全部保留原名原语义，其中两个此前**零生产调用方**，本次接成压缩链路的事后关卡：

| 监管函数 | 本次变化 |
|---|---|
| `runPreSupervision` / `runPostSupervision` | 不动（仍在 ②/⑨ 步） |
| `runCompressSupervision` | **新增调用点**：压缩后检查 `criticalEntriesLost`（SYSTEM_PROMPT / ROLE_DEFINITION / IMMUTABLE_CONSTRAINT）→ 命中即**否决压缩、回退原上下文**（对齐 ADR-0005）；`compressionRatio < 0.5` 只记录告警不阻断 |
| `runSummarySupervision` | **新增调用点**：记录摘要质量与压缩比（写入事件载荷） |
| `runLoopSupervision` / `runReasoningSupervision` | 不动 |

## 四、口径校准（源文档自相矛盾处，按叙述口径实现）

1. **§3.3 表格 vs §3.4/§6 叙述方向相反**
   - 表格：简单 `0.80` / 中等 `0.60` / 复杂 `0.40`
   - 叙述（§3.4 与 §6 各一次）：简单**更低**（50%-60% 就动手）、复杂**更高**（75%-85% 才动手）
   - 本实现取**叙述口径**：`simple 0.55 / medium 0.70 / complex 0.82`，理由是"简单问答优先压缩、复杂请求优先保留"的语义自洽，且该口径在文档中出现两次。

2. **`timestamp` 单位未定义**
   - 原文 `exp(-0.3 × age)` 若 `age` 取毫秒时间戳，衰减恒为 0（公式失效）。
   - 本实现把 `ContextChunk.timestamp` 固定为**轮次序号**（0,1,2…），公式保持 `exp(-0.3 × age)` 不变。

3. **§4.6 三层语义相似度**
   - 第 1 层（关键词/词元）已接为默认实现（复用 `Services/Retrieval/textScore.ts`）；
   - 第 2/3 层（轻量 embedding / LLM 重排）留**注入点**（`deps.semanticFn`），⚠️ 未在生产装配。

## 六、监控指标（§1.8 / §5.3）

`getCompactionMetrics()` 返回：运行次数、实际压缩次数、按层级计数、累计节省 tokens、
因收益不足跳过次数、被监管否决次数、累计耗时。

`CONTEXT_COMPRESSED` 事件载荷新增：`layer` / `decisionReason` / `complexity` / `triggerRatio` /
`usageRatio` / `appliedStrategies` / `droppedEntryTypes` / `gainRatio` / `promotedChunks` /
`cacheSensitivity` / `deltaCacheTokens` / `costCompact` / `costNoCompact` / `supervision.*`。

## 七、⚠️ 未接线 / 待办（诚实标注）

1. **`subtaskEnded` 信号无生产来源**：`runIteration` 目前不传该字段 → 子任务边界触发（§1.5）只在测试中生效。
2. **`subtask-isolation` 依赖标记约定**：消息内容须含 `[subtask:<id>]` 才会被识别；当前编排链路尚未写该标记 → 策略机在位但生产不触发。
3. **`prefixHitRate` 固定为 0**：真实 KV 前缀命中率未采集 → 成本模型实际退化为「不命中」一侧估算。
4. **`activeSubtasks` 未由编排提供**：`runIteration` 传空数组。
5. **Manual 层（§1.6）无 UI 入口**：`manualRequested` 已支持，但未接 `/compress` 命令或按钮。
6. **`MaxKeepRatio` 回插只在 complex 档生效**：`promoteRelevant=false` 的档位不做逐条回插。
7. **`runLoopSupervision` / `runReasoningSupervision` 仍未接**（本次范围外，与压缩无关）。
