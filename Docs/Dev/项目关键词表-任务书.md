## 1. 为什么要这份表（问题陈述）

项目已积累大量**同名不同义、同义不同名**的词汇，且这些词跨越设计文档、代码标识符、测试用例名、
实验矩阵、变更日志五类载体。当前症状：

- 同一概念在不同文档里叫法不一（例：`智体城邦` / `Civitas-AI`；`监管层` / `Supervision` / `治理`）
- 缩写无索引（`ADR`、`SLM`、`A2A`、`DUR-00x`、`G0–G13`、`L0–L5`、`BEN/ENV/SEC`、`P0-x`）
- 状态词在不同子系统含义不同（`superseded` 在记忆里是条目状态、在编排里是计划状态）
- 新人/编码代理无法从任一入口文档建立完整词汇视图

**目标**：给出唯一一份可检索的词汇事实源，并明确每个词条的**权威出处**（代码位置或文档章节）。

## 3. 取证方法（必须遵守）

1. **代码优先**：术语若在代码里有对应标识符，必须先 `grep`/`read` 该文件确认，再写 `路径:行号`。
   不允许凭文档叙述写代码位置。
2. **逐条给出证据**：每条的「权威出处」必须是你**实际打开过**的位置。若某术语只存在于文档（无代码），
   写成 `Docs/...md §x.y（仅文档）`。
3. **发现冲突必须两侧都记**：当代码与文档口径不一致时，词条里写「**代码说 X，文档说 Y**」，
   并在 `关联` 里指向冲突所在。**不要擅自选一个当正确**——那属于设计裁决，不在本任务范围。
4. **同名不同义要拆条**：例如 `superseded` 在不同子系统的含义不同时，拆成两条并以「所属层」区分。
5. **禁止编造**：查不到出处的术语**不要写**。宁可少写并在 §2.3 自检里如实标注缺口。

## 4. 口径裁定（已由项目负责人给定，直接采用，不要另行推断）

### 4.1 Benchmark 与 Tests 的分工

> **Benchmark 测的是 Agent 的数据流转问题，确保 Agent 没有问题；
> Tests 测的是接口能不能正常调用、代码有没有写漏内容。**

关键词表在 §14 必须严格按此措辞定义两者，并说明：

- Benchmark 的实验对象是**一个 Agent 跑一个任务**（能力轴）与**系统判定点**（系统轴）
- Tests 的实验对象是**函数/模块/接口**
- 两者的状态词、锚点词不要混用（见 4.3）

### 4.2 调用层规（Benchmark 侧的硬约束）

> 只能调用**被测层之上**的接口驱动实验（测工具 → 经 Core/Loop 调用；测单 Agent → 从 Core/Interface 调用）；
> **层下探针只用于监控、不用于驱动**。

此条是方法论约束，关键词表需收录 `层下探针`、`上层入口` 等词并给出上述定义。

### 4.3 实验矩阵词表（这些词必须收录且定义精确）

| 词 | 定义（照此写） |
|---|---|
| **双轴** | 实验矩阵由能力轴（6 面）与系统轴（九系统）两条轴构成，共用一张 `cells` 表，用 `axis` 区分 |
| **cell** | 一条可判定的实验判据（含 `oracle` 与锚点） |
| **面（surface）** | cell 的分组维度；能力面 6 个、系统面 9 个 |
| **锚点（anchor）** | 证明该 cell 的依据；`kind` ∈ `scenario` / `static` / `tag` / `spec` / `none` |
| **status** | `existing-covered` / `new-scaffold` / `gap` / `declared-only` |
| **new-scaffold** | 我可以做但还没做（改 Benchmark 即可转绿） |
| **gap** | **产品缺失**（改产品才能转绿）；缺口证明实验，不进 CI 阻断 |
| **declared-only** | 产品零实现，只登记语义与验收契约 |
| **attestation** | `executed`（Benchmark 场景真实跑过）/ `static`（仅 L0 静态对账）/ `tests`（由 Tests 承载）/ `none` |
| **落地率** | 只计 `existing-covered` 且 `attestation=executed`；`static` 单列不计 |
| **缺口证明实验** | oracle 今天必红的 cell，用于登记代码债 |
| **NOT-RUN** | 缺凭据导致**未执行被测行为**的用例，既不是失败也**绝不是通过** |
| **证据强度** | `behavioral`（检查行为/取值）/ `symbol`（只证明符号存在，不足以支撑覆盖声明） |

### 4.4 产品语义（已裁定，写入 §11 / §12 相关词条）

- **多模态** = 主模型通过**视觉工具（sightUse）**操作，或多模态模型原生支持
- **Agent 分裂** = Agent 可**自分裂**；为控制闭环，必须包含**自合并** ——
  两个 Agent 工作内容高度相似时合并，并**生成子代理继续工作**

## 5. 文档约定（必须遵守）

1. **命名**：产出文件必须为 `项目关键词表-qodercn-<yyyyMMddTHHmmss>.md`，落在 `Docs/Dev/`。
   —— 项目规定：**同类型/同职能的新文档一律带 `<来源>-<时间戳>` 后缀，且不得覆盖旧文档**。
2. **不重命名历史快照**：仓库中已有文档的名称不得改动。
3. **向代码看齐**：文档与代码不一致时，**以代码为事实**并在文档中如实记录差异（不擅自改代码）。
4. **禁止改代码**：本任务是**只读取证 + 写一份 Markdown**。除新建该 Markdown 外，**不得修改任何文件**
   （尤其不得动 `Src/`、`Tests/`、`Server/`、`Configs/`）。
5. **不处理无关文件**：工作区里可能同时存在其他工作线的未提交改动，**不要理会、不要清理、不要提交**。
