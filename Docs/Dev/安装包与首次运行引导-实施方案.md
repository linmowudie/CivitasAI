### 复现"自动化启动打包应用"的两个环境陷阱（本机实测踩到）

1. **`ELECTRON_RUN_AS_NODE=1` 必须在启动前清除**：该变量会让 `electron.exe` 退化成纯 Node——
   `import { app } from 'electron'` 报 `SyntaxError: does not provide an export named 'app'`，
   `require('electron')` 也拿不到真身。**这不是 Electron 的 ESM 限制**，是环境变量污染
   （本会话的 shell 里就带着它）。自动化脚本务必 `delete env.ELECTRON_RUN_AS_NODE`。
2. **受限 shell 下 Chromium 沙箱初始化失败 → 进程以 `0x80000003`（STATUS_BREAKPOINT）静默退出**：
   在自动化/无桌面会话里用 `--no-sandbox` 启动即可复现正常行为（实测加该参数后应用完整启动）。
   用户双击安装后的正常桌面会话不受影响。

### 本机遇到的一个环境限制（重要，需在正常桌面会话复核）

- **打包后的应用在本会话中无法写入 `C:` 盘**：`probeWrite()` 报 `EPERM: operation not permitted, mkdir/open 'C:\Users\…\CivitasAI…'`，
  导致**默认数据根 `%APPDATA%\CivitasAI` 在本机无法端到端跑通**（数据根改到 `F:`（工程所在盘）即完全正常，见上表）。
- 对照实验：`PowerShell`、`node.exe`、以及 **官方 Electron 二进制**（同一 `probeWrite` 代码）对 `C:\…\Temp`、`%APPDATA%`、`D:\` 写入**全部成功**；
  `Get-MpPreference` 显示 **未启用** Controlled Folder Access，也**没有** ASR 规则。
- 因此判定为**本会话环境对"未签名打包 exe"的文件写入限制**（DSH 沙箱或安全软件的信誉策略），**不是应用代码问题**；
  但也说明：**代码签名**不仅影响 SmartScreen 观感，也可能影响安全软件对写入/网络的行为，建议优先补上。
- 待办：在普通桌面会话（无沙箱）或签名后，复核默认 `%APPDATA%\CivitasAI` 数据根的一次完整首启。

## 2. 目录契约（第 1 阶段已实现）

### 2.1 三个根

| 变量 | 含义 | 缺省 |
|------|------|------|
| `CIVITAS_APP_ROOT` | 程序/资源根（**只读**）：`Configs/`（内置种子）、`Prompts/`、`Skills/`、`assets/`、`dist/` | 向上查找含 `Configs/default.json`（或 `package.json`）的目录 |
| `CIVITAS_DATA_ROOT` | 全局数据根（**可写**）：数据库 / 日志 / 密钥 / 用户配置 | 开发、便携 = `<APP_ROOT>/Data`；安装态由 Electron 注入 `%APPDATA%\CivitasAI` |
| `CIVITAS_WORKSPACE_ROOT` | 工作空间根（**可写**，体积大户）：会话工作目录 / 沙箱 / `.civitas` 备份 | 开发 = 数据根；便携 = `<便携 exe 目录>/Workspace`；安装 = `<安装目录>/Workspace`（只读则回落 `<DATA_ROOT>/Workspace`） |

细粒度覆盖与兼容变量：`CIVITAS_LOG_DIR` / `CIVITAS_CONFIG_DIR` / `CIVITAS_CONFIG_DIR_BUILTIN` / `CIVITAS_PROMPTS_DIR` / `CIVITAS_SKILLS_DIR` / `CIVITAS_BACKUP_DIR`；旧名 `CIVITAS_DATA_DIR` 仍生效。
模式判定只认显式信号：`CIVITAS_PORTABLE=1` / `--portable` / exe 同级 `.portable` 标记文件（打包本身**不再**等于便携）。

### 2.2 安装态落盘分布（实测）

```
%APPDATA%\CivitasAI\                     ← CIVITAS_DATA_ROOT
├── db\civitas_{main,events,memory}.db    ← 全局数据（卸载默认保留）
├── Logs\business.log  Logs\_Meta\
├── .secrets\providers.json.enc           ← API Key（safeStorage/DPAPI 加密）
└── Configs\local.json                    ← 用户覆盖层（首次运行引导写入，优先级最高）

<安装目录>\Workspace\                     ← CIVITAS_WORKSPACE_ROOT
├── workspaces\<sessionId>\               ← 每个任务的工作目录（工具沙箱根）
│   └── .civitas\                         ← 文件备份/改写基线（见 §5 待办）
├── Sessions\<sessionKey>\                ← 会话元数据
└── Loops\<sessionKey>\                   ← Loop 状态
```

### 2.3 配置覆盖层（首次运行引导的写入点）

```
内置(<APP_ROOT>/Configs)/default.json → {env} → 11 个功能文件 → local.json
用户(<DATA_ROOT>/Configs)/{env} → 功能文件 → local.json   ← 最高优先级
```
- ✅ 修复：`local.json` 现在可以覆盖 `modelRouter.routing` 等键（历史上被功能文件无条件回覆盖）。
- ⚠️ 口径保持：`env:` 引用**只在 `default`+`{env}` 层解析**；功能文件里的 `api_key_ref: "env:XXX"` 保持引用形态，由 Provider 层在请求期解析。

### 2.4 启动自检与失败提示

- 启动日志打印 `mode / app / data / workspace` 一行与可写性矩阵（`describePaths()`）。
- 数据根不可写时**抛带修复指引的错误**，Electron 用 `dialog.showErrorBox` 展示程序根/数据根/工作空间与实际错误（不再静默退出）。
- `ensureDirSafe()` / `probeWrite()` 永不抛错；工作空间不可写自动回落并记入告警。

## 3. 安装包与一键打包（第 1 阶段已实现）

- **形态**：Windows **NSIS 安装包为主 + 便携版保留**（`win.target = [nsis, portable]`）。
- **NSIS 关键项**：`oneClick:false`、`allowToChangeInstallationDirectory:true`（自选安装目录）、`perMachine:false`（默认装 `%LOCALAPPDATA%\Programs\CivitasAI`，**无需管理员**）、桌面/开始菜单快捷方式、`deleteAppDataOnUninstall:false`（卸载不删 `%APPDATA%` 数据）、安装器图标。
- **一键打包**：`npm run package`（= `node Scripts/package.cjs --nsis`），另有 `package:nsis` / `package:portable` / `package:dir` / `package:check`。
  - 首次打包需从 GitHub Releases 拉 Electron 运行时；本机 GitHub 不可达（`connect ETIMEDOUT`），脚本**默认注入 npmmirror 镜像**（外部已设同名变量则不覆盖，`--no-mirror` 可关）。
- **产物**：`release\CivitasAI-Setup-<version>.exe`（安装程序）、`release\CivitasAI-Portable.exe`（便携版）；脚本打印路径 + 体积 + SHA256。
- **图标**：`assets/icon.ico`（多尺寸）/`assets/icon.png`（512），由 `Scripts/genIcons.py` 生成（可重跑换图）；已确认图标被写入 exe 与安装包。
- **打包产物格式（重要）**：
  | 入口 | 格式 | 产物 | 说明 |
  |------|------|------|------|
  | `Src/main.ts` | ESM | `dist/main/Src/main.js` | 后端全量；必须带 `outbase:'.'`，否则单入口时产物会漂到 `dist/main/main.js` |
  | `electron/main.ts` | **CJS** | `dist/main/electron/main.cjs` | 主进程与 preload 统一 CJS，避免 ESM↔CJS 互操作差异；CJS 侧 `require('electron')` 拿到真身后注入后端 |
  | `electron/preload.ts` | CJS | `dist/main/electron/preload.cjs` | preload 必须 CJS |
- **未做**：代码签名（用户首次运行会看到 SmartScreen 提示，需"更多信息 → 仍要运行"）、自动更新（`electron-updater`）。
- **静默安装现状**：`/S` 静默模式下 electron-builder 的辅助式安装器**不写快捷方式与卸载注册表项**；企业批量部署前需另行验证（已写入 ELECTRON.md FAQ）。
