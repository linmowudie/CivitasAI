## 3. 实时通信方案

### 3.1 事件桥接层（原 WebSocket 连接管理）

> 原 WebSocket 连接管理已于 2026-09-28 删除，改由 Electron IPC 桥接（`electron/preload.ts` → 主进程 `Src/Interface/IpcBridge/ipcBridge.ts`）承担实时推送。前端统一入口为 `services/eventBusBridge.ts`，组件侧经 `hooks/useEventBus.ts`（组件 `useEventBus`）订阅。
>
> **2026-10-03 校准（D-15 / D-16）**：原代码块给出的 `class EventBusBridge { connect/send/subscribeWs/disconnect }` **在代码中不存在**——实际是**模块级函数**导出，且 **`subscribeWs` 这个名称已彻底不存在**（`hooks/useEventBus.ts` 导入的是 `connectBridge` + `subscribe`）。下方已换成真实签名。

```typescript
// Client/src/services/eventBusBridge.ts —— 实际导出（模块级函数，非 class）
export type BridgeMessage = { type: string; data: unknown; timestamp: number };
type MessageHandler = (msg: BridgeMessage) => void;

const FALLBACK_POLL_MS = 3000;              // 模块内硬编码常量（与 ui.* 配置无关，见 D-16/D-18）
function isElectron(): boolean;             // 检测 window.electronAPI?.onBackendEvent

/** Electron 模式：ipcRenderer.on('backend-event') 转发；浏览器模式：启动恢复检测轮询。两种模式都立即 setOnline(true) */
export function connectBridge(_url?: string): void;

/** 断开：停轮询 + connected=false + setOnline(false)。⚠️ 当前全仓零外部调用方（见 §3.2 离线横幅行） */
export function disconnectBridge(): void;

/** 订阅全部转发事件，返回退订函数（原命名 subscribeWs 已不存在） */
export function subscribe(handler: MessageHandler): () => void;

/** 命令上行：Electron 走 ipcRenderer.send('backend-command', JSON.stringify(msg))；浏览器模式仅 console.warn 后静默丢弃 */
export function send(message: Record<string, unknown>): void;
```

**浏览器开发模式的真实语义（D-16，原文"降级为 HTTP 轮询取事件"不成立）**：

- `eventBusBridge.ts` 内部函数 `startFallbackPolling` **不拉取任何事件**，只做一件事——每 `FALLBACK_POLL_MS`（硬编码 3000ms）检测 `isElectron()` 是否变为可用，一旦可用就停轮询并 `connectBridge()`；
- 因此**浏览器模式下前端事件通道实际为空**，实时性完全依赖各 store 的 REST 拉取兜底（`useDashboardData` / `useApprovalPolling` / 视图内 `hydrate()`）；
- ⚠️ **目标态**：若要浏览器模式具备事件下行能力，需后端补 `/api/events` 增量端点后接真轮询（待办）。
