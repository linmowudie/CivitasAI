## 2. 视图模块

### 2.1 城邦大屏（Dashboard）

> 核心原则：每个可视化元素必须解释实际问题或支持决策，禁止仅为展示而生成无实质价值的图表。

| 区域 | 可视化内容 | 业务意义 |
|------|-----------|---------|
| 系统状态卡片 | 活跃任务数、活跃 Agent 数、系统 Token 总量 | 快速了解系统整体运行状态 |
| Agent 活跃状态图 | 力导向图：节点=Agent，边=通信关系，颜色=状态 | 直观展示当前协作拓扑和 Agent 健康状态 |
| Token 流向桑基图 | 桑基图：系统池→Agent 钱包→消耗/税收/分润 | 理解 Token 的分配和消耗路径 |
| 任务进度时间线 | 甘特图：各任务的子任务执行时间线 | 追踪任务执行进度和瓶颈 |
| 仲裁案件状态 | 卡片列表：进行中的仲裁案件 + 状态 | 监控仲裁效率和积压情况 |
| 异常告警 | 告警列表：最近的异常事件 | 快速发现和响应系统问题 |

### 2.2 任务面板（TaskPanel）

| 组件 | 功能 |
|------|------|
| 任务提交区 | 文本输入框 + 提交按钮，支持流式输出预览 |
| 任务列表 | 所有任务的状态（进行中/已完成/失败） |
| 任务详情 | 子任务拆解视图、各 Worker 进度、质量评分 |
| 流式输出 | WebSocket 实时推送 Agent 的推理过程 |

### 2.3 Agent 监控（AgentMonitor）

| 组件 | 功能 |
|------|------|
| Agent 列表 | 所有 Agent 的状态、角色、Token 余额 |
| Agent 详情 | 执行历史、Token 消耗曲线、操作日志 |
| Agent 拓扑图 | 当前协作关系的可视化（Director-Partner-Worker） |

### 2.4 Token 账本（TokenLedger）

| 组件 | 功能 |
|------|------|
| 钱包总览 | 系统池余额、各 Agent 钱包余额 |
| 交易流水 | 按时间排序的交易记录，支持筛选 |
| 消耗统计 | 按 Agent/模型/任务维度的消耗柱状图 |
| 税率趋势 | 税率随时间变化的折线图 |

### 2.5 仲裁视图（ArbitrationView）

| 组件 | 功能 |
|------|------|
| 案件列表 | 所有仲裁案件的状态和结果 |
| 案件详情 | 证据对比、裁决过程、恢复状态 |
| 仲裁者池状态 | 当前仲裁者数量、负载 |

## 3. 实时通信方案

### 3.1 WebSocket 连接管理

```typescript
// 前端 WebSocket 服务
class WebSocketService {
  private ws: WebSocket;
  private reconnectAttempts = 0;
  private maxReconnectAttempts = 5;
  
  // 连接
  connect(url: string): void;
  
  // 发送消息
  send(message: ClientMessage): void;
  
  // 订阅消息类型
  on(type: string, handler: (data: any) => void): void;
  
  // 断线重连（指数退避）
  reconnect(): void;
}
```

### 3.2 实时推送事件

> **本节不维护数值**（SSOT 裁决）。下表的频率均由 `Configs/default.json → ui.*` 提供（Docs/11 §2.1）；事件名引用 `Docs/07 §4.3` 注册表，**前端不得自接新事件字符串**。

| 事件 | 推送方式 | 节流配置键 | 数据量 |
|------|---------|-----------|--------|
| 任务进度更新 | WS 推（`task:progress`） | 状态变化即推，无节流 | 小 |
| Agent 状态变化 | WS 推（`agent:*` 域） | 同上 | 小 |
| Token 消耗 | WS 推（`token:consumed`） | 同上 | 小 |
| 流式输出 | WS 推（`agent:stream_chunk`，收尾 `agent:stream_end`） | `ui.streamFlushIntervalMs`（默认 100ms 批量合并，**禁止逐 token 推送**） | 中 |
| 会话消息 | WS 推（`agent:chat_message`）+ REST 补齐 | 状态变化即推 | 小 |
| 仲裁状态 | WS 推（`arbitration:` 域） | 状态变化即推 | 中 |
| 大屏概览 | HTTP 轮询 | `ui.dashboardPollIntervalSec`（默认 5 秒） | 中 |
| 审批队列 | HTTP 轮询 + `loop:approval_requested` 推 | `ui.approvalQueueRefreshSec`（默认 3 秒） | 小 |

**前端约束**：
- 本地事件缓冲上限 = `ui.maxEventBufferSize`，超限丢弃最旧项（**不阻断主流程**）；
- WS 断开重连：退避基数 `ui.wsReconnectBackoffMs`，最多 `ui.wsReconnectMaxAttempts` 次，耗尽后降级为纯轮询并显示离线横幅；
- 展示层的百分比均 ×100 渲染，内部存储一律 0.0–1.0（Docs/10 §1.1）。

## 6. 可观测性设计

### 6.1 日志追踪

| 维度 | 实现 | 说明 |
|------|------|------|
| trace_id | 贯穿所有 Agent 调用 | 一个任务从开始到结束的全链路 |
| span | 每次 LLM 调用、工具执行 | 记录耗时、Token 消耗 |
| 关联 | operation_id 关联具体操作 | 工具调用、文件操作 |

### 6.2 监控指标

| 指标类别 | 具体指标 | 采集方式 |
|---------|---------|---------|
| 系统健康 | 活跃 Agent 数、任务队列长度、内存使用 | 定时采集 |
| 性能 | 任务平均完成时间、LLM 调用延迟 P50/P95 | 事件驱动 |
| 成本 | 总 Token 消耗、每任务平均成本、税率 | 交易驱动 |
| 质量 | 任务成功率、Agent 开除率、仲裁案件数 | 状态变化驱动 |

### 6.3 告警规则

| 告警 | 条件 | 级别 |
|------|------|------|
| Token 异常消耗 | 单 Agent 5 分钟消耗超预算 | Critical |
| 任务积压 | 任务队列长度 > 10 | Warning |
| Agent 高失败率 | 近 10 次任务失败率 > 50% | Warning |
| 仲裁积压 | 待处理仲裁案件 > 5 | Warning |
| 系统 Token 不足 | 系统池余额 < 10000 | Critical |
