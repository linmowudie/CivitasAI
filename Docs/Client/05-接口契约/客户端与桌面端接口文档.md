# 客户端与桌面端接口文档

> **端归属**：`Client/src/**`（前端 React 渲染层）+ `electron/**` 与 `Src/Interface/IpcBridge/**`（Electron 桌面桥）。按 `Docs/README.md` 三端分类，本文属 **Client 端（前端与 Electron 客户端）**。
>
> **范围**：渲染进程可用的**全部对外接口**——`window.electronAPI`（IPC 通道 51 条）、客户端服务层封装、事件订阅/命令协议、账号服务端 HTTP 调用、凭据安全存储。**不包含**：
> - 主进程内本地后端的 HTTP 控制面 → 见 [`Docs/Agent/14-参数总典与接口契约/本地后端接口文档.md`](../../Agent/14-参数总典与接口契约/本地后端接口文档.md)
> - 云端账号服务 REST API → 见 [`Docs/Server/01-服务端/REST-API接口文档.md`](../../Server/01-服务端/REST-API接口文档.md)
> - AI 组件族专属桥接契约 → 见 [`Docs/Client/03-AI组件族架构/后端接口契约.md`](../03-AI组件族架构/后端接口契约.md)
>
> **事实源**：`electron/preload.ts`、`electron/main.ts`、`Src/Interface/IpcBridge/**`、`Client/src/services/**`。**代码为唯一事实源**；抽取基线 2026-10-17。

## 1. 运行形态与环境检测

| 形态 | 判定 | 可用能力 |
|---|---|---|
| Electron 桌面端 | `window.electronAPI?.onBackendEvent` 存在 | IPC 通道全量（读 + 命令）、原生对话框、DPAPI 安全存储 |
| 浏览器开发态 | 无 `electronAPI` | 仅 HTTP 读（经主进程不可用；`eventBusBridge` 退化为轮询探测，`send()` 静默丢弃命令并告警） |

> **硬约束**：视图层禁止直接操作 `ipcRenderer`/`fetch` 外网，一律经 `Client/src/services/**`。
> 凭据（云端令牌、供应商 API Key、DPAPI 加密）**只存在于主进程**，渲染进程只持有短期引用。

## 2. `window.electronAPI` 通道全表（51）

### 2.0 `window.electronAPI` 分组结构（调用形态）

`preload.ts` 暴露的是**分组对象 + 顶层函数**，调用形态如下（分组名即 API 表面，改名=破坏契约）：

| 分组（`window.electronAPI.*`） | 函数 |
|---|---|
| `onboarding` | `getPaths` `getState` `testProvider` `verifyModels` `writeUserConfig` `patchState` `complete` `skip` `reset` |
| `secureStore` | `isAvailable` `get` `set` `remove` |
| `modelProviders` | `getProviders` `addProvider` `removeProvider` `fetchModels` `getRouting` `updateRouting` `getModels`；嵌套 `modelProviders.a2aSync.{listUnsynced,markSynced,applyPulled,stats}` |
| `sessions` | `list` `create` `update` `archive` `listMessages` `addMessage` |
| `todos` | `list` `clear` |
| `configs` | `get` |
| `data` | `getMemoryEntries` `getLongTermMemory` `bulkLongTermMemory` `getStatsEvents` `getSkills` `getCustomTools` |
| `device` | `getFingerprint` |
| `secrets` | `saveProviders` `loadProviders` |
| 顶层 | `getServerPorts()` `getApiToken()` `getAppVersion()` `pickDirectory()` `openPath()` `openExternal()` `setAccountServerOrigin()` `serverFetch()` `onBackendEvent()` `sendBackendCommand()` |

> 渲染进程**只允许**通过该对象的白名单方法访问主进程；`preload` 不透传 `ipcRenderer`/`require`/`fs`。

> 方向：`invoke` = 请求-响应（`ipcRenderer.invoke` ↔ `ipcMain.handle`）；`send` = 单向（`ipcRenderer.send` ↔ `ipcMain.on`）；
> `event` = 主进程 → 渲染进程广播（`webContents.send`）。
> 所有通道都由 `electron/preload.ts` 白名单暴露；主进程处理位置见下表。

## 3. 客户端服务层契约（`Client/src/services/**`）

### 3.1 `ipcApi.ts` — IPC 的类型化封装（**视图层唯一入口**）

所有 IPC 调用都必须经此模块；模块内部做"Electron 不可用 → 返回 `{ok:false,error:'Electron API 不可用'}`"的降级，不抛出。

| 分组 | 函数 | 关键 DTO |
|---|---|---|
| 供应商/路由 | `ipcGetProviders` · `ipcAddProvider` · `ipcRemoveProvider` · `ipcFetchProviderModels` · `ipcGetRouting` · `ipcUpdateRouting` · `ipcGetModels` | `ProviderInfo` · `RoutingConfig` · `RoutingUpdateResult{ok,data,error,rejected[],invalid[]}` · `ModelSpec` |
| 会话/消息 | `ipcListSessions` · `ipcCreateSession` · `ipcUpdateSession` · `ipcArchiveSession` · `ipcListMessages` · `ipcAddMessage` | `ChatSession{session_id,title,status,created_at,updated_at,work_dir}` · `ChatMessage{message_id,session_id,role,content,model,tokens_used,trace_id,created_at}` |
| 配置/记忆/技能/工具 | `ipcGetConfig` · `ipcGetMemoryEntries` · `ipcGetLongTermMemory` · `ipdBulkLongTermMemory` · `ipcGetStatsEvents` · `ipcGetSkills` · `ipcGetCustomTools` | `MemoryEntry` · `LongTermMemoryDto` · `SkillEntry` · `ToolInfo` · `DerivedStatsResult` |
| 设备/凭据 | `ipcGetDeviceFingerprint` · `ipcSaveProviderSecrets` · `ipcLoadProviderSecrets` | `ProviderSecretData` |
| 引导 | `hasOnboardingApi` · `ipcGetAppPaths` · `ipcGetOnboarding` · `ipcTestProvider` · `ipcVerifyModels` · `ipcWriteUserConfig` · `ipcPatchOnboarding` · `ipcCompleteOnboarding` · `ipcSkipOnboarding` · `ipcResetOnboarding` | `AppPathsDto` · `OnboardingSnapshotDto` · `ProbeResultDto` · `ModelVerificationDto` · `VerifyModelsResultDto` |
| A2A 同步 | `ipcA2AListUnsynced` · `ipcA2AMarkSynced` · `ipcA2AApplyPulled` · `ipcA2ASyncStats` | 同步条目 DTO |
| 系统 | `ipcOpenPath` | — |

关键 DTO（节选）：

```ts
ProbeResultDto = { ok, baseUrl, listOk, chatOk, models: DiscoveredModelDto[], suggestedModel?, latencyMs?,
                   error?, errorKind?, hint?, listStatus?, listAttempted?, chatAttempted?, listNotProvided?,
                   providerMessage?, keySanitized?, chatModelUsed?, chatCandidates?, chatAttempts?, modelsFromFallback? }
DiscoveredModelDto = { id, context_window, max_output, supports_vision, supports_tools, cost_per_1k_input, cost_per_1k_output }
RoutingUpdateResult = { ok, data?, error?, rejected: string[], invalid: {path,reason}[] }
```

### 3.2 `eventBusBridge.ts` — 事件订阅 / 命令下发

```ts
BridgeMessage = { type: string; data: unknown; timestamp: number }
connectBridge(url?): void      // Electron：订阅 onBackendEvent；浏览器：降级轮询探测
disconnectBridge(): void
subscribe(handler): () => void // 返回退订函数
send({ type, payload }): void  // Electron → backend-command；浏览器 → 静默丢弃 + warn
```

- 视图层只允许经 `subscribe()` 拿事件；**不得**直接监听 `ipcRenderer`。
- 命令类型见 §2.7；生成过程的结果通过事件回传（`agent:stream_chunk` → `agent:iteration_complete` → `agent:stream_end`）。

### 3.3 `serverApi.ts` — 云端账号服务 HTTP 客户端

| 导出 | 语义 |
|---|---|
| `normalizeServerUrl(raw)` / `setServerBaseUrl` / `getServerBaseUrl` | 基地址规范化（无 scheme 补 `http://`，去尾斜杠） |
| `configureServerAuth(hooks)` | 注入登录态钩子：`getTokens()` / `refresh()` / `onAuthLost(reason)` |
| `serverRequest<T>(method, path, {body?, token?})` | 直接请求（不自动刷新） |
| `authedRequest<T>(method, path, opts)` | 带令牌请求；401 → 调用 `refresh()` → 重放；刷新失败 → `onAuthLost` + 失败返回 |

- 传输：**必须**经主进程 `server-fetch` 通道（渲染进程不直连外网）。
- 主进程白名单：只放行"本机后端端口"或渲染进程显式固定过的 origin（`set-account-server-origin`）；未固定等于拒绝——防止渲染进程把内网代理出去。
- 返回：`ServerResult<T> = { ok: true, data } | { ok: false, error: { code, message, status? } }`。

### 3.4 `secureStore.ts` — 安全存储探测

`probeSecureStorage()` / `getSecureStore()` / `isSecureStorage()`：探测 DPAPI 可用性并给出存储实例；不可用时**降级要显式告知用户**（不得静默把密钥落到明文）。

### 3.5 `syncService.ts` — 记忆/设置/任务/统计/备份同步

使用的云端端点（详见服务端文档 §4）：`GET /v1/memories`、`POST /v1/memories/bulk`、`GET/PUT /v1/settings`、`GET /v1/tasks`、`POST /v1/tasks/bulk`、`POST /v1/stats/events`、`GET /v1/stats/overview`、`GET /v1/backup`、`POST /v1/restore`。

关键导出：`pullAll` / `pushAll` / `fetchAllServerMemories` / `mapMemoryStatus` / `mapStatusToLocal` / `toServerMemoryItem` / `toLocalMemoryEntry` / `extractPrefs` / `gatherLocalPrefs` / `applyPrefsToRuntime` / `exportBackup` / `restoreBackup`。

| `a2aSync.ts` | `pushA2A` / `pullA2A` / `syncA2A` / `redactForUpload` / `toServerItem` / `defaultA2ASyncDeps` | A2A 消息上行/拉回（上行前脱敏） |

## 4. 安全边界（实现约束，不得绕过）

| 边界 | 规则 | 依据 |
|---|---|---|
| 凭据不出主进程 | 供应商 API Key / 云端令牌只经 `secure-store-*` 与主进程内存传递；渲染进程不落盘明文 | `electron/main.ts`、`secureStore.ts` |
| 外联白名单 | 渲染进程不能任意 `fetch`：必须经 `server-fetch`，且目标 origin 必须在白名单（本机后端端口或已固定的账号服务 origin） | `electron/main.ts`、`serverApi.ts` |
| preload 最小暴露 | 只暴露上表 51 条通道，不透传 `ipcRenderer`/`require`/`fs` | `electron/preload.ts` |
| 本机控制面身份门 | 浏览器开发态经 `/internal/api-token` 领取凭据（仅回环、POST、`Origin` 回环、`no-store`） | `Src/Interface/WebServer/apiToken.ts` |
| 身份验真 | 审批裁决的 `decidedBy` 不可直接采信：`user` 绑定当前活动账号，Agent 角色必须真实注册且角色匹配；带云端令牌时先向账号服务验真（失败 fail-closed 403） | `Src/Interface/RestApi/approvalApi.ts` |

## 5. 与其它端的对接速查

| 客户端要做的事 | 走哪条通道 | 落到哪一层 |
|---|---|---|
| 读会话/消息/待办/配置/记忆/技能/工具 | IPC `ipc-*`（§2.4–2.5） | 主进程 Services → 本地库 |
| 发起/停止生成 | `backend-command`（`generate_reply`/`stop_generation`） | 主进程 `ipcBridge.handleCommand` → AgentRuntime/Loop |
| 接收流式与状态 | `backend-event` → `eventBusBridge.subscribe` | 主进程 EventBus 广播 |
| 管理模型供应商 | IPC `ipc-*provider*` | 主进程 modelRouter + 加密凭据 |
| 账号登录/同步 | `server-fetch` → `/v1/**` | 云端账号服务 |
| 首次运行引导 | IPC `ipc-*onboarding*` | 主进程 onboarding 服务 |

## 6. 维护约定

- 新增 IPC 通道：必须同时改 `electron/preload.ts`（白名单 + 类型）+ 主进程 `ipcMain.handle` + `ipcApi.ts` 封装 + 本文表格；缺一不可（漏 preload 白名单 = 渲染进程永远 pending）。
- 新增命令类型：改 `ipcBridge.handleCommand` 的 `case` 分支 + §2.7 + `eventBusBridge` 调用点。
- 新增云端调用：必须经 `serverApi`（不得在组件里直接 `fetch`），并按需在 `set-account-server-origin` 白名单登记。
- 本文与源码不一致时：**源码 > 本文**，改代码必须回写本文，并在 `Docs/CHANGELOG.md` 登记。
