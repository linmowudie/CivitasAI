## 0. 设计目标

将 Canvas 原型中验证的 **三栏自适应工作界面** 落地为生产前端，替代当前 `AppLayout.tsx` 的"左侧导航 + 主内容区"二栏结构。核心改进：

1. **三栏布局**：左侧副容器（任务/功能入口）| 主容器（多视图内容）| 右侧副容器（Agent 预览/文件/终端）
2. **统一交互规则**：左侧任务项/功能项、右侧 L1 Agent 列表项均驱动主容器内容切换（`MainView` 单一数据源）
3. **AI 组件族集成**：主容器内的 Agent 回复区域使用 `ai-components/` 的 Core/Harness/Loop/Memory 族组件渲染，由 `AIEventBus` + `Subscribe` 声明式订阅驱动
4. **暗色主题一致性**：沿用 Canvas 原型的色板（`#0e0e0e` / `#161616` / `#1c1c1c` / `#8b5cf6`），与现有 `index.css` 设计语言对齐

> **2026-10-03 校准（目标 3）**：**部分达成**——Core/Harness 族已实际参与渲染，但走的是 `chatStore.segments` + `components/Chat/MessageBubble.tsx`（薄组合层）**静态组合**路线；`Subscribe` 在生产代码中 **零调用**，Loop/Memory/MultiAgent 族仅存空注册函数。事件驱动路线为 ⚠️ 未实现/目标态，详见 §4.2.1、§8.1 校准注。
>
> **2026-10-03 校准（目标 4）**：**基底层色值已被代码改掉**——`Client/src/index.css` 的 `--color-surface-950` 现为 `#000000`（注释自陈：与 Electron `titleBarOverlay` 纯黑标题栏无接缝），`#0e0e0e` 全仓 0 命中；`#161616`/`#1c1c1c`/`#8b5cf6` 仍对应 `surface-900`/`surface-800`/`brand-500`。本条以代码为准表述为"最底层为纯黑"，色板裁定事项见 §6（❓【需人工裁定】）。

## 2. 状态管理设计

### 2.1 MainView 统一状态（单一数据源）

Canvas 原型定义了 `MainView` 联合类型，所有点击操作（左侧任务/功能项、右侧 Agent 列表项）统一驱动此状态：

```typescript
type MainView =
  | { type: 'conversation' }          // 默认对话视图
  | { type: 'task'; id: string }      // 任务详情视图
  | { type: 'feature'; id: string }   // 功能视图（approvals/loop-tasks/harness/memory/data-hub/skills/mcp/custom-tools/profile/settings）
  | { type: 'agent'; id: string };    // Agent 对话视图
```

**落地方案**：创建 `stores/uiStore.ts`（Zustand），管理 `mainView` + `setMainView`，供左右面板和主容器共同消费。

**实际实现（2026-10-03 校准，按 `stores/uiStore.ts` 回写）**：

```typescript
// stores/uiStore.ts
export type PreviewKind = 'agent' | 'subagent' | 'plan' | 'terminal'
                        | 'summary' | 'fileview' | 'filepreview';   // 7 种（原规格 6 种）

const PANEL_MIN = 120;
const PANEL_DEFAULT = 220;

interface UIState {
  mainView: MainView;
  setMainView: (view: MainView) => void;
  // 左侧面板
  leftPanelOpen: boolean;            // 初始 true
  leftPanelWidth: number;
  toggleLeftPanel: (open?: boolean) => void;
  setLeftPanelWidth: (w: number) => void;      // 下限 PANEL_MIN
  expandedFeatures: Set<string>;
  toggleFeature: (id: string) => void;
  // 右侧面板
  rightPanelOpen: boolean;           // ⚠️ 初始 false（规格未定义默认值）
  rightPanelWidth: number;
  toggleRightPanel: (open?: boolean) => void;
  setRightPanelWidth: (w: number) => void;     // 下限 PANEL_MIN
  activePreview: PreviewKind;
  setActivePreview: (kind: PreviewKind) => void;
  visitedTabs: Set<PreviewKind>;     // 初始含 'agent'
  markTabVisited: (kind: PreviewKind) => void;
  previewFile: string | null;        // ⚠️ 尚无消费方，见 §5.3
  setPreviewFile: (file: string | null) => void;
}
```

> **2026-10-03 校准（CANVAS-02，正向 + 3 点补注）**：`uiStore` 已按本节落地，字段与规格逐条对应，且补齐了规格未写的面板 toggle/宽度 setter/`toggleFeature`/`markTabVisited` 动作。差异需记录：
> 1. **无持久化中间件**：宽度与开合状态仅存内存，刷新即回默认；`rightPanelOpen` 默认 `false`（关联 §7.3 ❓【需人工裁定】）。
> 2. `setMainView` 除切视图外还有一个副作用：从 `conversation` 切走时调用 `hotReloadStore.flushOnNavigate()`（热重载待生效提示），规格未登记。
> 3. `previewFile` / `setPreviewFile` **除 `uiStore` 自身外全仓零调用**（§5.3 文件联动未交付）。

### 2.2 交互规则（统一点击行为）

以下两类点击操作 **均** 触发 `setMainView()`，驱动主容器标题栏 + 内容区同步更新：

| 触发源 | 目标 MainView | 示例 | 实现载体（2026-10-03 校准） |
|---|---|---|---|
| 左侧**会话任务**项 | `{ type: 'conversation' }`（并置 `chatStore` 当前会话） | 点击"实现 Agent 编排引擎" → 主容器切回该会话对话流 | `LeftPanel/TaskList.tsx` 的 `openSession()`：`setActiveSession` + `setActiveConversation` + `setActiveAgent` + `setMainView({type:'conversation'})` |
| 左侧**后台任务**项 | `{ type: 'task', id: taskId }` | 点击"后台任务"分组内条目 → 主容器切换到任务详情 | `LeftPanel/TaskList.tsx` 的 `renderBackendTask()`（`taskStore.tasks` 非空时才出现该分组） |
| 左侧"新任务"按钮 | `{ type: 'conversation' }` | 点击"+ 新任务" → 创建会话并进入对话视图 | `LeftPanel/NewTaskButton.tsx` 的 `handleClick()` |
| 左侧功能项（无子项） | `{ type: 'feature', id: featureId }` | 点击"审批 / Loop 任务 / 记忆 …" → 主容器切换到对应功能视图 | `LeftPanel/FeatureList.tsx` 主项 `onClick`（有子项者改为 `toggleFeature`） |
| 左侧功能子项 | `{ type: 'feature', id: childId }` | 点击"Skill" → 主容器切换到技能列表 | `LeftPanel/FeatureList.tsx` 子项 `onClick` |
| 右侧 L1 Agent 列表项 | `{ type: 'agent', id: agentId }` | 点击 `agent-prime_director-…` → 主容器切换到 Agent 视图 | `RightPanel/AgentPreview.tsx` 的 `setMainView({type:'agent', id: a.agentId})` |

> **2026-10-03 校准（CANVAS-03）**：原表把"左侧任务项"一律映射为 `{ type: 'task', id }`，与代码不符。**FE-021** 修复后，左侧主列表承载的是**会话任务**（`chat_sessions`），点击只切 `conversation` + 当前会话；`{ type: 'task' }` 视图现在**仅由"后台任务"分组（`/api/tasks`）进入**，而后台任务在常规对话链路下通常为空，故 task 视图实际可达性很低（关联 §4.2.2）。`id` 亦由"agentName"更正为 **agentId**（`agentStore` 的 `agents[].agentId`）。

### 8.3 EventEmitter 架构适配

根据 `Docs/Client/03 §4A`，本项目是 Electron 桌面应用，前后端在同一 Node.js 进程中。通信方式从 WebSocket 简化为 EventEmitter（**现为 Electron IPC 双通道**）：

- **后端事件源**：`Src/Services/EventBus/eventBus.ts`（`EventEmitter` 封装，暴露 `publish` / `createEvent` / `subscribeMany`；事件枚举在 `Src/Services/EventBus/eventTypes.ts`）
- **主进程桥接**：`Src/Interface/IpcBridge/ipcBridge.ts` 的 `startIpcBridge()`——
  - **下行**：`subscribeMany(Object.values(EventType), …)` 收全部领域事件 → 组装 `{ type, data, timestamp }` → 遍历 `BrowserWindow.getAllWindows()` 执行 `win.webContents.send('backend-event', msg)`；
  - **上行**：`ipcMain.on('backend-command', …)` 解析 JSON 命令帧 `{ type, payload }` → `handleCommand()`（`generate_reply` / `stop_generation` 等）；另有 **25 个** `ipc-*` 请求-响应通道（`ipcBridge.ts` 的 `registerIpcHandlers()`：会话/消息/待办/配置/记忆/技能/自定义工具/密钥/设备指纹等）；
  - 非 Electron 环境直接空操作（HTTP/REST 模式仍保留在 `Src/Interface/RestApi/`）。
- **前端接收侧**：`Client/src/services/eventBusBridge.ts`（`connectBridge()` → `electronAPI.onBackendEvent`，`send()` → `electronAPI.sendBackendCommand(JSON.stringify(msg))`；浏览器模式仅告警丢弃，见缺陷清单 FE-001）
- **前端分发侧**：`Client/src/hooks/useEventBus.ts`（**原 `useWebSocket.ts`**，文件头保留"替代原 useWebSocket hook"注记）由 `AppLayout.tsx` 的 `AppLayout()` 全局挂载一次 → 写入 `stores/eventStore.ts` 缓冲 + 分发到 `agent/task/approval/token/chat/system` 等各 store。

> **2026-10-03 校准（CANVAS-18，两处路径/API 校正）**：原文写"后端 `Src/Core/EventBus/eventBus.ts`"与"主进程 `eventBus.on('*')`"**均与代码不符**——① eventBus 实位于 `Src/Services/EventBus/`（`Src/Core/EventBus/` 不存在）；② `eventBus` 无通配监听 API，广播由 `ipcBridge.ts` 的 `startIpcBridge()` 用 `subscribeMany(Object.values(EventType), …)` 逐类型注册实现。另：原文"前端 `services/eventBusBridge.ts` 使用 `ipcRenderer.on('backend-event')`"方向正确，实际经 `electron/preload.ts` 暴露的 `electronAPI.onBackendEvent` 封装，不直接触碰 `ipcRenderer`。
