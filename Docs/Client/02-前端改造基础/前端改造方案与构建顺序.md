## 2. 目标架构

> **2026-10-03 校准**：原分层图中的 `Interface/WebSocket ← WS:3001 → services/ws.ts` 整条通路已随 IPC 迁移删除（`Client/src/services/ws.ts` 不存在）。下图按现状重画；HTTP 与 IPC 为**并存双通道**，Electron 模式下会话/模型等读写优先走 IPC（零 HTTP 开销），浏览器开发模式仅 HTTP。

```
后端  Interface/RestApi  ←── HTTP :3000（Vite 代理 /api）──→  services/api.ts (原生 fetch)
      Interface/IpcBridge ←── Electron IPC（主进程直调）──→  services/ipcApi.ts (invoke/handle)
                                          ↑ 下行 backend-event / 上行 backend-command
                                             services/eventBusBridge.ts（替代原 ws.ts）
                                                   ↓ 事件名严格取自 shared/eventTypes.ts（genEventTypes.ts 生成）
                                             hooks/useEventBus.ts（组件侧唯一事件入口）
                                                   ↓
                                             stores/* (Zustand，现 15 个) ← 唯一状态源
                                                   ↓
                                             hooks/* (useDashboardData / useApprovalPolling / useAlerts)
                                                   ↓
                                             views/* → components/*（纯展示，不直连网络）
```

铁律：
1. **视图层禁止出现 `fetch`/`new WebSocket`**，一律经 `services/` → `stores/`；
2. **前端不得自定义事件字符串**，事件名从后端 `eventTypes.ts` 生成 `Client/src/shared/eventTypes.ts`（F0.6 产出，构建期脚本同步）；
3. 展示百分比 ×100，内部 0.0–1.0；UI 参数一律读 `Configs/default.json → ui.*`，禁止硬编码数值。

> **2026-10-03 校准 · 三条铁律现状对账（违例均未消除）**
> - **铁律 1**：`Client/src` 内 `new WebSocket` 0 命中 ✅（原生 WebSocket 路线已整体作废），`services/api.ts` 用 `fetch` ✅。但**跨层直连仍有两处**：`Client/src/components/Layout/MainContainer/FeatureView.tsx`（组件层 import `apiGet` 并请求 `/api/memory/entries`、`/api/skills`、`/api/tools/custom`）与 `Client/src/views/TokenLedger.tsx`（视图层 import `apiGet` 请求 `/api/tokens/wallets`），均跳过 hooks/stores。⚠️ **目标态未达成**——待办：取数下沉到 store（memory/skills/tools 目前无对应 store）。
> - **铁律 2**：裸字符串事件名违例 2 处——`Client/src/stores/approvalStore.ts`（`applyEvent()` 内比较 `'loop:approval_requested'` / `'loop:approval_decided'` / `'loop:approval_timeout_rejected'`）与 `Client/src/stores/todoStore.ts`（模块级 `const TODO_EVENT_TYPE = 'agent:todo_updated'`），未取 `shared/eventTypes.ts`。前端镜像本身也**落后一个事件**（后端 `Src/Services/EventBus/eventTypes.ts` 72 个 vs `Client/src/shared/eventTypes.ts` 71 个，缺 `AGENT_TODO_UPDATED`），说明 `Scripts/genEventTypes.ts` 未重跑。⚠️ 待办：`npm run gen:event-types` 重生成 + 两处改枚举取值。
> - **铁律 3**：`ui.*` 四个键（`dashboardPollIntervalSec`/`approvalQueueRefreshSec`/`streamFlushIntervalMs`/`maxEventBufferSize`）**均无消费方**，前端一律硬编码常量：`Client/src/stores/chatStore.ts` 的 `const FLUSH_INTERVAL_MS = 100`（注释自陈对应 `streamFlushIntervalMs`）、`Client/src/stores/eventStore.ts` 的 `const TRIM_TO = 500`（对应 `maxEventBufferSize`）、`Client/src/hooks/useDashboardData.ts` 的 `const POLL_INTERVAL = 5000`（对应 `dashboardPollIntervalSec`）、`Client/src/hooks/useApprovalPolling.ts` 的默认形参 `intervalMs = 30_000`（**与 `ui.approvalQueueRefreshSec=3` 数值不一致**）。⚠️ **目标态未达成**——待办：改读 `configStore`/IPC 配置；注意 `Client/src/config/configSchema.ts` 已把 `ui.streamFlushIntervalMs`、`ui.maxEventBufferSize` 暴露为可编辑项，但改值对运行时行为无效（设置面板与真实行为脱钩，风险高于纯硬编码）。
> - **例外登记**：`ui.wsReconnectBackoffMs` / `ui.wsReconnectMaxAttempts` 两键全仓 0 命中且从未存在，随 WS 路线一并作废（见 F1.3）。

**~~WS 约定~~ → IPC 帧约定（2026-10-03 校准，原 WS 段整体作废）**

> 原文：端口 3001；服务端帧 `{ type, data, timestamp }`；客户端帧 `subscribe` / `unsubscribe` / `get_dashboard` / `get_approvals` / `ping`；前端只允许从 `src/shared/eventTypes.ts` 取值（F0.8 生成）。

现状（权威载体为 `Src/Interface/IpcBridge/ipcBridge.ts` 与 `Client/src/services/eventBusBridge.ts`，Electron IPC 双通道，**不再有 3001 端口**）：

- **下行（主进程 → 渲染进程）**：`startIpcBridge()` 用 `subscribeMany(Object.values(EventType), …)` 订阅后端 EventBus 全量事件，封装为 `{ type, data, timestamp }` 后 `win.webContents.send('backend-event', msg)` —— **帧形与旧 WS 约定完全一致**，`type` 仍直接取 `EventType` 成员值（如 `loop:started`、`agent:stream_chunk`）；渲染侧由 `eventBusBridge.connectBridge()` → `hooks/useEventBus.ts` 分发到各 store。
- **上行（渲染进程 → 主进程）**：`ipcMain.on('backend-command', (e, raw))` 收 `JSON.stringify({ type, payload })`，由 `handleCommand()` 分派；帧集合由原 5 值**扩为 7 值**：`subscribe` / `unsubscribe` / `get_dashboard` / `get_approvals` / `ping` + 迁移新增的 `generate_reply`（流式生成，替代旧 HTTP 触发路径）与 `stop_generation`（F2 的 Stop）。
- **请求-响应**：`registerIpcHandlers()` 注册 **24 个 `ipc-*` handle**（providers/routing/models/sessions/messages/todos/config/memory/long-term/skills/custom-tools/device-fingerprint/secrets/stats-events 等），前端统一包装在 `Client/src/services/ipcApi.ts`。
- ⚠️ **待清理**：`Configs/default.json` 的 `server.wsPort=3001` 已无任何消费方（仅 `Src/Infra/Config/configValidator.ts` 仍校验其为整数），属死配置键；`Configs` 侧删除前需同步校验器与文档，登记为待办。
- **铁律 2 不受迁移影响**：事件名仍只允许取自 `Client/src/shared/eventTypes.ts`（`Scripts/genEventTypes.ts` 生成）；当前镜像落后一个事件的违例见 §2 铁律 2 校准。
