## 0. 契约目标与原则

### 0.1 核心目标

明确后端 **EventEmitter 事件推送**的 **Schema 规范**,确保前端 AI 组件能正确解析和渲染,同时保证 **向后兼容性**。

> **2026-10-03 校准**：两点与代码实态不符，已按现状回写——① 进程内总线**不是** Node `EventEmitter`，而是自研 publish/subscribe 实现（`Src/Services/EventBus/eventBus.ts`：`publish` / `createEvent` / `subscribe` / `subscribeMany` / `getEventLog`，带 eventId 幂等 + 事件环形日志，无 `emit`、无 `on('*')`）；② 契约对象不止事件面，还含前端实际调用的 REST/IPC 端点，现状登记见新增 **§10**（是否纳入签署范围待裁定）。

### 0.2 架构简化说明

**原设计**：前后端通过 WebSocket(端口 3001)通信,需维护复杂的连接管理/心跳/重连逻辑。

**简化后**：由于本项目是 **Electron 桌面应用**,前后端运行在同一 Node.js 进程中,改用 **进程内事件总线 + Electron IPC** 双段链路。（2026-10-03 校准：原文"Node.js EventEmitter"表述不准确，见 §0.1 注）

| 维度 | WebSocket | EventEmitter |
|------|-----------|--------------|
| 通信方式 | `ws://localhost:3001` (TCP) | `eventBus.emit()` (内存)（2026-10-03 校准：实为 `publish(createEvent(...))` + `subscribeMany(...)`） |
| 延迟 | 5-10ms | <0.1ms |
| 代码量 | ~370 行 | ~50 行（2026-10-03 校准：实际桥接体 `ipcBridge.ts` 为 1122 行，含事件转发 + 7 个命令 case + 25 个 `ipc-*` invoke 通道（另有 `electron/main.ts` 的 8 个基础通道），原估严重低估） |
| 端口管理 | 需维护 wsPort | 无需端口 |

**影响**：
- 后端：删除 `Src/Interface/WebSocket/` 目录(wsGateway/wsServer/wsHandler),新增 `Src/Core/EventBus/eventBus.ts`
  - 2026-10-03 校准：`Src/Interface/WebSocket/` 确已清空（仅剩 `.gitkeep`）✔；但**没有** `Src/Core/EventBus/` —— 总线在 `Src/Services/EventBus/eventBus.ts`，IPC 桥接在 `Src/Interface/IpcBridge/ipcBridge.ts`（入口函数 `startIpcBridge` / `stopIpcBridge`，由 `Src/main.ts` 调用）。
- 前端：`Client/src/services/ws.ts` 重写为 `eventBusBridge.ts`(使用 Electron IPC)
  - 2026-10-03 校准：成立。`ws.ts` 已删除；事件面为 `Client/src/services/eventBusBridge.ts`（`connectBridge` / `subscribe` / `send`），请求-响应面另有 `Client/src/services/ipcApi.ts`（封装 `window.electronAPI` 各命名空间）与 `Client/src/services/api.ts`（HTTP fetch 封装，含 429 退避）。渲染进程**不直连** `ipcRenderer`，一律经 `electron/preload.ts` 的 contextBridge 白名单。
- 配置：`Configs/default.json` 原计划删除 `wsPort` 字段，现状为字段**保留**但已无实际 WS 服务（作为历史遗留字段存在，前端走 IPC，不再使用该端口）
  - 2026-10-03 校准：仍成立（`server.wsPort: 3001` 保留、无任何监听者；HTTP 实绑 `server.httpPort: 3000`）。**本文原 `providerBaseUrl: http://localhost:3001` 因此两头都不存在**，见 §6.3 校准。

### 0.3 设计原则

| 原则 | 说明 | 示例 |
|------|------|------|
| **必填字段不可删除** | 已发布的必填字段永远不能删除，只能标记为 deprecated | `subgroup` 一旦设为必填，就不能改回可选 |
| **新增字段必须可选** | 新字段第一个版本必须是可选的，2 个版本后才能考虑改为必填 | `idempotencyKey` V1 为可选，V3 才可能必填 |
| **枚举值只能扩展** | 枚举类型只能新增值，不能删除或修改现有值 | `riskLevel` 可增加 `critical`，但不能删除 `low` |
| **类型不可变更** | 字段类型一旦发布，不能从 `string` 改为 `number` | — |
| **提前通知破坏性变更** | 若必须做破坏性变更，需提前 2 个版本通知，并提供迁移指南 | — |

> **2026-10-03 校准 · 原则与实态的现状记录**（不裁决，仅登记）：
> - 五条原则中"必填字段不可删除 / 新增字段必须可选"在本文档自身被违反过：§3.1 / §3.3 / §3.4 原文列出的 `value` / `version` / `namespace` / `concurrentWrites` / `resolutionStrategy` / `cycleLength` / `evidence` / `suggestedAction` 等字段**从未出现在实发 payload 中**（属"文档单方面新增"），本次已按实发回写并在原位标注 ⚠️ 目标态。
> - `CHANGELOG.md` 现有事件相关条目仅为 `eventTypes` 的增删（`AGENT_ITERATION_COMPLETE` + 前端镜像同步），**没有** §6.2 事件域版本号（`v1.2.0 → v1.3.0` 一类）的变更记录 —— 即 §6.3 第三条验收"版本变更需在 CHANGELOG.md 中记录"目前无执行痕迹。
> - **待办**：① 确认契约是否已生效（见 §9【需人工裁定】）；② 若生效，补"事件域版本变更 → CHANGELOG"流程；③ 明确破坏性变更的评审人。

### 7.2 事件格式错误处理

若后端推送的事件不符合 Schema（如字段类型错误），**契约设想**的行为：

1. **捕获错误**：AIBubbleContainer 的 ErrorBoundary 捕获
2. **显示 Fallback**：渲染 `<InvalidEventFallback eventType={event.type} />`
