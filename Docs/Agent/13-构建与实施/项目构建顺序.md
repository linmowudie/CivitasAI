# Civitas-AI 项目构建顺序

> 本文档规定 **实现顺序与依赖链**。所有阶段严格按序推进，每阶段末尾有"通过门槛（Gate）"，未通过不得进入下一阶段。
>
> **推导依据**（四条硬约束，不可违背）：
> 1. **五层单向依赖红线**（Docs/Agent/02 §1.1）→ 构建方向必须自底向上：`Infra → Tools → Services → Core → Interface`；
> 2. **启动 18 步的运行时依赖顺序**（Docs/Agent/02 §7.1，章节标题现为「启动 18 步（+ ⓪ / ⑦.1 / ⑦.2 / ⑦.3 / ⑰.2 子步；与 `Src/main.ts` 实际代码对齐）」）→ 同一层内部的初始化次序即构建次序；
>    > **2026-10-03 校准**：原写"启动 **14 步**"已失效——上游文档与 `Src/main.ts` 的 `startServer()` 装配步数均已扩至 18 步。本文 S1 所述"①~⑦"是这 18 步中的**前七步子集**（Config/Logging/Time/Security/Fs/Db/Workspace），不是步数总量。
> 3. **副作用不可重复原则**（Docs/Agent/12 §4）→ 任何有副作用的模块必须晚于 `DurableExecution`；
> 4. **Loop 成熟度递进**（Docs/99 附录 B）→ 多 Agent 能力必须晚于 L2 受控闭环，否则冲突面按 `O(n²)` 放大。

