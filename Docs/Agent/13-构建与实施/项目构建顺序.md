# Civitas-AI 项目构建顺序

> 本文档规定 **实现顺序与依赖链**。所有阶段严格按序推进，每阶段末尾有"通过门槛（Gate）"，未通过不得进入下一阶段。
>
> **推导依据**（四条硬约束，不可违背）：
> 1. **五层单向依赖红线**（Docs/02 §1.1）→ 构建方向必须自底向上：`Infra → Tools → Services → Core → Interface`；
> 2. **启动 14 步的运行时依赖顺序**（Docs/02 §7.1）→ 同一层内部的初始化次序即构建次序；
> 3. **副作用不可重复原则**（Docs/13 §4）→ 任何有副作用的模块必须晚于 `DurableExecution`；
> 4. **Loop 成熟度递进**（Docs/99 附录 B）→ 多 Agent 能力必须晚于 L2 受控闭环，否则冲突面按 `O(n²)` 放大。
>
> **禁止跨阶段抢跑的关键规则见 §3。**

## 3. 禁止抢跑清单（硬性阻断）

| 禁止 | 原因 |
|------|------|
| S2 之前实现任何写文件/发网络请求的工具 | 副作用无 INTENT 日志 → 崩溃后必然重复执行（Docs/13 §4） |
| S4 之前实现 `Core/Loop` | 工具缺 `idempotency/reversibility` 契约，`wrapToolCall` 无处可挂 |
| S6 之前实现多 Agent（S10/S11） | 命中失效一+四+五，冲突面按 `O(n²)` 放大，不可调试 |
| S5 之前实现 `Supervision` 六模块之外的业务监管 | 违反"中间件在外、监管在内、禁止互相替代"红线 |
| S6 之前把 `LoopState` 存进 `SharedMemory` | Context ≠ State 红线；压缩会吃掉任务事实（Docs/07 §8.1） |
| S9 之前实现 UI 交互 | API 形状未定，必然返工 |
| S12 之前实现"Agent 开除其他 Agent" | 无审批门与终止理由，等于无监管自治 |
| 任一 Gate 未过就进入下一阶段 | 缺陷会向下游按依赖链放大 |
