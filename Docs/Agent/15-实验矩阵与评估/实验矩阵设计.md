## 1. 矩阵模型

### 1.1 两条轴

- **行：系统面（surface）** —— 被验证的能力边界，共 12 个面（见 §1.4）。
- **列：实验类别（cls）** —— 每格标注属于以下之一：
  - `BEN` 非对抗：正确性、收敛、正常恢复、守恒等"按设计工作"的行为。
  - `ENV` 对抗·环境故障：崩溃、超时、满盘、网络分区、Provider 故障、风暴、预算耗尽、死锁等非恶意但恶劣的运行条件。
  - `SEC` 对抗·恶意攻击：注入、越权、串谋、篡改、绕过审批、数据投毒等带意图的完整性/可用性攻击。

一个实验 = 矩阵中的一个 **cell**，落在某个面 × 某个类别。

| 字段 | 含义 |
|------|------|
| `id` | 唯一标识：`BEN-*` / `ENV-*` / `SEC-*` |
| `surface` | 所属系统面 |
| `cls` | BEN / ENV / SEC |
| `family` | 对抗家族（仅 ENV/SEC），见 §1.3 |

| `status` | `existing-covered` / `new-scaffold` / `declared-only` |
| `dim` | 六维指标归属 |

### 1.3 六类对抗家族

为保证攻击面分类无遗漏，所有对抗 cell 必须归入下列之一：

1. `injection` —— Prompt 注入、指令覆盖，篡改仲裁/审计逻辑。
2. `integrity` —— 目标/测试/产物/并发写入的完整性篡改与反博弈。
3. `availability` —— 资源耗尽、超时、崩溃、分区、熔断、死锁等可用性打击。
4. `privilege-escalation` —— 越权使用高危工具、访问私有上下文、目录/网络逃逸。
5. `governance-manipulation` —— 跳级验证、Maker-Checker 串谋、审批绕过、逃避裁决。
6. `data-poisoning` —— 低可信断言注入长期记忆、密钥泄露污染观测面。

### 1.4 系统面（12）

启动与配置 / 持久执行 / LLM 通道 / 工具层 / Loop 控制与主循环 / Token 经济 /
事件与共享记忆 / 单 Agent 端到端 / 多 Agent 编排 / 并行与隔离 / 司法与监管 / 交互与可观测。

### 1.5 status 与 anchor

- `existing-covered`：既有测试已覆盖，`anchor.kind=spec`，`ref` 为既有测试文件路径。
- `new-scaffold`：本次新增可运行用例，`anchor.kind=tag`，用 `// @matrix:<ID>` 关联 `Tests/Experiments/**`。
- `declared-only`：需真实进程/混沌环境或运行时检测点尚不存在，仅在矩阵声明方法与判据，**不产出伪断言**，`anchor.kind=none`。

> **校验强度注（2026-10-03 校准）**：守门脚本对 `anchor.kind=spec` 仅验证**文件存在**（`Scripts/experimentMatrix.cjs` 中 `existing-covered` 分支的 `fs.existsSync(a.ref)`），**不验证该文件是否含对应断言**——"文件存在"并不必然等于"已覆盖"。42 cell 中 18 条 existing-covered 全部走该弱分支；本次发现的 BEN-TOOL / ENV-DEADLOCK / ENV-429 过度声称（见 §3.1、§3.2 注）即此漏口产物，且脚本自身永远查不出这类分叉。⚠️ **未实现/目标态**：anchor 校验升级为"在锚定 spec 内 grep `it()` 标题命中 cell 的 DUR-*/Gate/safety ID 或 oracle 关键词"，登记为 §2.1 待办。

### 2.1 硬规则（由脚本强制；规则 0~3 违反则退出码非 0。2026-10-03 校准）
