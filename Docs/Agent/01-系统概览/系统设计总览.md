## 1. 系统定位

### 1.1 产品愿景

Civitas-AI 是一个**基于 Loop 工程与 Harness 工程构建的社会驱动型自治多 Agent 系统**。系统由分级权限的 Agent 构成：**治理级 Agent（仲裁庭 / 监管局 / 审计局，L0）监管与仲裁执行级 Agent（L2）的工作**，以维持系统长期自主运行；**入口级 Agent（Prime Director / Partner，L1）可自分裂（招募 Partner / Worker）协作攻坚困难任务**，而 Worker 等执行级 Agent 只能由上层指派、不可自行招募下级。系统以 Prime Director 为中枢，根据任务复杂度自主决定组织形态，并内置司法、行政、税务等治理机制，实现自我纠错、资源管控与生态平衡。

### 1.2 核心隐喻

| 现实隐喻 | 系统映射 | 核心职责 |
|---------|---------|---------|
| 总经理 | Prime Director | 需求解析、模式决策、全局编排 |
| 合伙人 | Partner | 联合攻坚高难度任务 |
| 员工 | Worker | 执行细分任务 |
| 流水线工人 | Assembly Line | 按 SOP 执行标准化任务 |
| 法院 | Arbitration Tribunal | 处理 Agent 间纠纷 |
| 政府 | Regulatory Authority | 跨域协调、全局规则维护 |
| 税务局 | Resource Audit Bureau | Token 监控、异常稽查、征税 |

## 2. Agent 类型定向（ADR-0000）

### 2.1 五元组

```
[A2 | B3 | C1 | N4 | R2]
```

| 轴 | 取值 | 含义 |
|----|------|------|
| D1 自主度 | A2 | 自由循环 — Prime Director 多步规划（评估→决策→招募→追踪→汇总） |
| D2 副作用面 | B3 | 执行命令/写外部系统 — Agent 写代码文件、执行命令、调用外部 LLM API |
| D3 上下文主导源 | C1 | 用户即时输入 — 主上下文来自用户需求，Agent 间通信是衍生上下文 |
| D4 交互拓扑 | N4 | 多 Agent 编排 — 动态组织、多角色协作 |
| D5 时效要求 | R2 | 交互流式 — 用户等待 Agent 工作，期望流式反馈 |

### 2.2 判定路径

决策树：Q1(输出非纯文本) → Q2(非 GUI 操作) → Q3(步骤不可预穷举，动态路由) → Q4(需要多专精角色分工 + 互相审查) → **T6 多 Agent 协作型**

### 2.3 T6 升级信号验证

| # | 信号 | 命中情况 |
|---|------|---------|
| 1 | 上下文不可容纳 | 多角色独立上下文（Director/Partner/Worker/Tribunal/Audit 各自私有） |
| 2 | 需要互相审查 | 仲裁庭多数决（⚠️ 未实现/目标态——2026-10-03 校准：`Services/Arbitration/tribunal.ts` 当前为规则裁决模拟，3-LLM 多数决未接 LLM，详见 §4.6）+ 资源审计局独立稽查 |
| 3 | 工具集互斥 | Worker 最小工具集 vs Director 全局权限 vs Audit 只读稽查 |
| 4 | 时效量级不同 | 主任务交互流式(R2) vs 稽查/审计可离线(R1) |

### 2.4 与默认画像（T3）的差异

| 配置项 | T3 默认值 | T6 定向值 | 理由 |
|--------|----------|----------|------|
| 主循环形态 | 10 步自由循环 | 编排层循环 + Worker 内层循环（⚠️ 目标态——2026-10-03 校准【需人工裁定】现状记录+待办：当前代码编排层无循环、子 Agent 无内层循环，`executeLoop` 唯一生产调用点在 IPC 的 PD 链路；现状与待办详见 §4.1 校准注） | 需要 Director 全局调度 |
| `max_iterations` | 30（`loopDefaults.max_iterations`） | 仍按角色单层限定（`roleOverrides[role].max_iterations`），但**另叠加全局墙钟与 Token 预算**（`stopRules.limits.*`） | 多 Agent 协作需全局视角，但单层上限不得取消 |
| 工具面 | 四级全开 | Worker 各自持最小工具集，禁止共享全量工具 | 安全隔离 |
| 安全信任模型 | 三级 | 每个 Worker 独立信任边界；跨 Agent 调用记为操作历史 | 沙箱隔离 |
| 分区预算上限 | S15% / L15% / M15% / H45%（`context.partitionCeilingRatio`） | **Phase 0–2 仍用同一默认值**；“Director L 大 / Worker H 大”为待实现目标，需先登记 `context.partitionCeilingByRole[role]`（Docs/Agent/10 §2.8） | 角色职责不同，但无键不得实现 |
| 历史与记忆 | 三类历史全量 | `trace_id` 跨 Agent 传播，Worker 各自 `operation_id` | 审计追溯 |
| 评测主指标 | 六维全量 | 端到端完成率 + 成本/任务 + 错误恢复率 | 协作效率优先 |

## 3. 角色体系

### 3.1 角色定义

| 角色 | 代号 | 实例化方式 | 生命周期 | 信任等级 |

## 4. 核心机制摘要

### 4.1 七种工作方式（路由模式）

> **2026-09-22 校准**：本节原写"六种路由模式"，且清单缺 `DIRECT`、含 `AUDIT`，与代码不符。现统一表述为 **7 种工作方式**，即前端 `WorkingMode`（`Client/src/stores/chatStore.ts` 类型 `WorkingMode`；2026-10-03 校准：改为符号定位，原注行号已漂移）。
> 后端 `RoutingMode`（`Src/Core/Decision/types.ts:12-18`）只有 **6 个成员**：`DIRECT / DELEGATION / ASSEMBLY_LINE / CONSORTIUM / LITIGATION / REGULATION`——**不含 `AUDIT`**（税务稽查不经编排路由，由监管/稽查服务链路 `Services/Audit/resourceAuditBureau.ts` 承载）；其中 `LITIGATION` / `REGULATION` 在类型定义上已标注 **S12**。

| 模式 | 代号 | 触发条件 | 参与角色 | 产出物 | 后端 `RoutingMode` | 实现状态 |
|------|------|---------|---------|--------|:------------------:|---------|
| 直接执行 | `DIRECT` | 简单任务（预估 Token ≤ 10K） | PD | 直接答复 | ✓ | ✅ S10 已接线 |
| 高难攻坚 | `CONSORTIUM` | 预估 Token > 50K 或需 ≥ 2 个不同专业域 | PD + 1~N 个 PT | 《联合开发契约》 | ✓ | ✅ S10 已接线 |
| 并行委派 | `DELEGATION` | 任务可拆解为低耦合子任务 | PD + 1~N 个 WK | 《任务分配书》 | ✓ | ✅ S10 已接线 |
| 流水线 | `ASSEMBLY_LINE` | 任务流程高度确定性、可预定义 SOP | AL 节点序列（**2026-10-03 校准**：编排器流水线节点当前以 `role:'worker'` 实例化——`orchestrator.ts executeAssemblyLine`；`assembly_node` 角色仅列于 `agent.recruit` 可招募白名单，编排侧无实例化路径，待接线） | SOP 执行结果 | ✓ | ✅ S10 已接线 |
| 司法仲裁 | `LITIGATION` | Agent 间不可调和冲突 | AR (3-LLM)（⚠️ 3-LLM 当前为规则模拟，见 §4.6——2026-10-03 校准） | 《裁决书》 | ✓（标 S12） | ⚠️ 待接线（S12） |
| 行政协调 | `REGULATION` | 跨域重大事件或全局规则更新 | RG | 广播通知 / 规则更新 | ✓（标 S12） | ⚠️ 待接线（S12） |
| 税务稽查 | `AUDIT` | Token 消耗异常触发 | AU | 稽查报告 / 冻结令 | ✗（仅前端 `WorkingMode`） | ⚠️ 待接线（S12，走稽查服务链路） |

> **2026-10-03 校准（【需人工裁定】现状记录 + 待办，D-05）**：上表"✅ S10 已接线"的实态是**路由与招募登记可达**——编排器四模式执行函数（`orchestrator.ts executeDirect/executeDelegation/executeAssemblyLine/executeConsortium`）创建/招募子 Agent 后仅将 assignment 置 `status:'assigned'` 并登记进度即返回 success，**不驱动子 Agent 主循环执行**；`agent.recruit` 返回 `dispatch:'pending'`；`executeLoop` 唯一生产调用点在 IPC 的 PD 链路（`ipcBridge.ts`），前端所选 `workingMode` 入参当前在 `startStreamGeneration` 中以 `_workingMode` 挂起未消费。**待办**：本列与 §2.4"主循环形态"的措辞是否降格为"✅ 路由可达 / ❌ 子 Agent 执行未接线"，需人工裁定后统一修订。

### 4.2 路由判定规则（已精确定义）

**Director 评估流程：**
1. 接收用户需求 → 生成结构化复杂度评估报告（**2026-10-03 校准**：当前为**启发式规则评估**——`Src/Core/Decision/complexityAssessor/complexityAssessor.ts assessComplexity()` 以关键词识别专业域 + 文本长度估算 Token，`assessorModel:'heuristic-v1'`，SOP 匹配为硬编码 4 条模板；原"1 次 LLM 调用生成结构化评估报告"为 ⚠️ 未实现/目标态（Phase 后续接 LLM 评估，见 Docs/Agent/03 §3.2））
2. 评估报告包含：预估 Token 消耗、所需专业域列表、任务耦合度评分
3. 按规则路由：

| 条件 | 路由 |
|------|------|
| 预估 Token > 50K **或** 专业域 ≥ 2 | `CONSORTIUM` |
| 任务可拆解为低耦合子任务（耦合度 < 0.3） | `DELEGATION` |
| 任务匹配已有 SOP 模板 | `ASSEMBLY_LINE` |
| 其他（简单任务，预估 ≤ 10K） | `DIRECT`（PD 直接执行） |

> 阈值键已登记于 `Configs/routingRules.json`。**2026-10-03 校准**："可热更新"为 ⚠️ 未实现/目标态——运行期决策实际读取 `Src/Core/Decision/routeDecision/routingRules.ts` 的模块内默认常量（`DEFAULT_RULES`，经 `getRoutingRules()` 取用），`updateRoutingRules()` 全仓无生产调用；热更新底座未启动：`Infra/Watcher/configWatcher.ts startWatching()` 无调用方（`main.ts` 仅调 `initConfigWatcher`），`detectChanges()` 为空实现（仅记录快照不扫描）。
>

### 4.3 交付判定标准

| 失败类型 | 判定条件 |
|---------|---------|
| 格式不符 | 输出不符合任务分配书定义的输出 Schema |
| 质量不达标 | 由四级 Verifier（L1→L4，独立 Reviewer Agent 运行）判定不通过；Director 仅消费 Verifier 结果，**不直接评分**（Docs/Agent/03 §7.1 红线）。旧口径"Director 评估输出质量评分 < 60/100"已废弃（2026-09-22 校准） |
| 执行超时 | 超过任务分配书约定的 `maxIterations` 或时间上限 |
| 显式放弃 | Worker 显式上报无法完成。**2026-10-03 校准**：原"Worker 返回 `UNABLE_TO_COMPLETE` 标记"**未实现/目标态**（全仓 0 命中）；代码实态为 Worker 经 `Tools/Custom/submitForReview` 提交评审、终止归因用 `TerminationReason` 四值 `capability / laziness / goal_unreasonable / external_error`（`Core/Decision/types.ts`，配套 `Services/Recruitment/terminationRationale.ts`） |

**容错规则：** 连续 3 次失败 → 开除并重新招募。阈值可配。

> **2026-10-03 校准（容错规则）**：① "阈值可配"⚠️ 未兑现——判定阈值实际取运行期常量 `orchestrator/progressTracker.ts TRACKER_THRESHOLDS.consecutiveFailureLimit`（=3）；`Configs/supervision.json agentConsecutiveFailuresToExpel` 无 TS 消费者（配置键已登记）。② 连续失败判定存在，但**开除重募链路未接线**：`Services/Recruitment/recruiter.ts expelAgent / expelAndReplace` 无生产调用方（仅测试与内部互调）。

### 4.4 Token 分润模型

```
Agent_i 分润 = 总Token池 × (Wq×质量分 + Wn×数量分 + We×效率分) / Σ(所有Agent综合分)

默认权重：Wq = 0.5, Wn = 0.3, We = 0.2
```

| 维度 | 度量方式 | 默认权重 |
|------|---------|---------|
| 产出质量 | 交付物被最终采纳的比例（Director 判定）（⚠️ 见下方校准注——2026-10-03 校准） | 0.5 |
| 产出量 | 有效输出 Token 数 | 0.3 |
| 效率 | 实际耗时倒数 | 0.2 |

> **2026-10-03 校准（【需人工裁定】现状记录 + 待办，D-28）**：公式与默认权重与 `Services/TokenEconomy/profitDistributor.ts`（`DEFAULT_WEIGHTS`，权重和为 1 校验在位）一致；但 ① `calculateDistribution / executeDistribution` **无生产调用方**（仅 `TokenEconomy/index.ts` 再导出 + Tests），分润结算链路未接线；② `qualityScore` 只由调用方注入，代码中不存在"Director 判定采纳率"的任何实现——与 §4.3 已废弃"Director 评分"的口径自相矛盾；③ `Configs/economyRules.json economy.profitSharing` 权重无运行期消费者（代码硬编码 `DEFAULT_WEIGHTS`）。**待办**：质量分口径是否统一改挂 Verifier 结果、"算法已就绪、结算链路与质量分来源未接线"的正式表述，需人工裁定。

### 4.5 异常消耗检测

| 判定规则 | 默认阈值 | 说明 |
|---------|---------|------|
| 滚动窗口超限 | 5 分钟内消耗 > 单 Agent 预算的 80% | 预算默认 10K tokens/5min |
| 偏离均值 | 当前轮消耗 > 该 Agent 近 10 轮均值的 3 倍 | 防止缓慢泄漏 |
| 循环检测（编排侧） | 连续 3 次输出相似度 > 0.85 | 疑似死循环/幻觉重复（**2026-10-03 校准**：`orchestrator/progressTracker.ts TRACKER_THRESHOLDS`，阈值硬编码常量） |
| 循环检测（稽查侧） | 最近 5 轮输出指纹高度重复（去重后 ≤ 2 种指纹） | **2026-10-03 校准**（原文只有一条"3 次相似度 0.85"，实为两套独立规则）：`Services/Audit/anomalyDetector.ts DEFAULT_CONFIG.loopConsecutiveRounds`（=5，`Configs/audit.json` 同值），**不比相似度数值**——`loopSimilarityThreshold: 0.85` 仅作告警展示字段 |

**处置流程：** 触发 → 警告（日志）→ 二次触发 → 冻结 Agent + 通知 Director

> **2026-10-03 校准（处置流程，D-12）**：与代码不符，实态为——**critical 级告警一步即冻结**（`resourceAuditBureau.monitorAgent`：任一 critical 告警即 `freezeAgent`，无"二次触发才冻结"计数；warning 不冻结）；冻结后自动解冻由 `Configs/audit.json freezeAutoUnfreezeSec`（3600 秒）与稽查复核（`investigate` 判误报即 `unfreezeAgent`）支撑；"通知 Director"**未实现/目标态**。且 `monitorAgent` 当前在 `Src/` 内无生产调用方（仅 Tests），**稽查链路整体待接线**（详见 Docs/Agent/06）。

### 4.7 动态仲裁者数量控制（来自思考1）

冲突频率与 Agent 数量的关系：$f = k \cdot n^{m}$（$m > 1$，超线性增长）

**动态调整策略：**
- 核心层仲裁者：固定 1 个，处理常规冲突
- 辅助层仲裁者：按冲突监测指标动态增减
- 调整触发：连续 3 个时间窗口冲突频率超阈值 → 增加辅助仲裁者
- 资源约束：仲裁者总数 ≤ min(C/c_i, B/b_i)，受计算资源和通信资源双重约束

### 4.8 治理型共享记忆（来自思考2）

1. 写入拦截 → 2. 胶囊调阅 → 3. 裁决推理 → 4. 律师函挂起 → 5. 现场恢复 → 6. 知识沉淀

## 7. 全局 ID 定义

三个核心 ID 的语义在全部分系统中必须一致，禁止混用：

| ID | 粒度 | 生成时机 | 格式 |
|----|------|---------|------|
| `session_key` | 一个逻辑会话（用户维度） | 会话首次创建时 | SHA-256 前 16 位十六进制 |
| `trace_id` | 一次 Agent 运行会话（运行维度） | 运行启动时 | UUID v4 |
| `operation_id` | 单次工具调用/文件操作 | 操作发起时 | `{timestamp_ms}-{4位随机hex}` |

**T6 扩展：** 跨 Agent 传播时复用同一 `trace_id`，新增 `parent_agent_id` 字段登记父子关系，禁止新造第三类追踪 ID。

> **2026-10-03 校准（三 ID 现状）**：
> - `session_key`（**D-16**）：⚠️ 设计态/休眠——SHA-256 前 16 位十六进制的生成器 `Infra/Workspace/sessionKeyGenerator.ts generateSessionKey()` 无生产调用方（仅 `index.ts` 再导出 + Tests），使用 `sessions` 表的 `Infra/Db/Repositories/sessionRepository.ts` 在 `Src/` 内 0 消费者。运行期实际会话主键为**两套 `sess-` 前缀 ID**：`Interface/RestApi/chatApi.ts` 生成 `sess-<uuid8>`（表 `chat_sessions`）与 `Services/Session/sessionManager.ts` 生成 `sess-<ms>-<base36>`。**三套并存，运行期以 `chat_sessions.session_id` 为准**；本表格式列为设计目标。
> - `trace_id`（**D-17**）：实际有两种来源——REST/ALS 链路为 UUID v4 ✓（`Infra/Logging/traceContext.ts randomUUID()`、`Interface/RestApi/taskApi.ts uuidv4()`）；但 IPC 主用户链路目前生成时间戳短码 `trace-<ms>-<hex4>`（`Interface/IpcBridge/ipcBridge.ts startStreamGeneration`），⚠️ 待统一，挂 §8.1"trace_id 跨 Agent 不可变"红线一并跟踪。
> - `operation_id`（**D-18，【需人工裁定】现状记录 + 待办**）：`traceContext.generateOperationId()` 的时间戳段实际为 **base36**（`Date.now().toString(36)`），与本表 `{timestamp_ms}` 十进制口径不符（代码注释亦自称 timestamp_ms，自相矛盾）；另有同族手写 ID——`LoopControl/middleware/toolSafetyGate.ts` 以十进制 `${Date.now()}-${hex4}` 作 effectId。**待办**：裁定"以文档十进制 ms 为准修码"或"文档补注 base36"，避免与 Docs/Agent/14 §6 再次分叉。

| **每个 Loop 至少 5 类退出** | 成功 + 上限 + 预算 + 无进展 + 风险，缺一拒发（**2026-10-03 校准（D-21）**：原写"4 类"为误——所列本身即五种；`Services/LoopControl/stopRules.ts EVALUATION_ORDER` 恰为 `risk / limits / budget_hard / no_progress / success` 五项判定，`StoppedReason` 共 8 值，与 Docs/Agent/11 §2.1、Docs/Agent/02 的"五类退出"口径对齐。"缺一拒发"的启动期校验 ⚠️ 未实现/目标态——当前无该校验，落点见 Docs/Agent/11 §2） | Docs/Agent/11 §2 |
