## 1. 接入模型

本地后端有三种对外面：

| 面 | 入口 | 使用者 | 现状 |
|---|---|---|---|
| HTTP 控制面 | `http://{host}:{httpPort}` 的 `/api/**` | 浏览器开发态 / 本机受控客户端 / Electron 主进程转发 | ✅ 80 条路由 |
| IPC 桥 | Electron `ipcMain` 通道 | 渲染进程（桌面形态，**主通道**） | ✅ 51 通道（见客户端文档） |
| 事件总线 | EventBus → `backend-event` IPC 广播 | 渲染进程（订阅） | ✅ 83 种事件 |

> `Src/Interface/WebSocket/` 目录**只有 `.gitkeep`**：原 WebSocket 服务层已被 IPC 桥替代（见 `Client/src/services/eventBusBridge.ts` 注释）。
> 浏览器开发态的**命令下发**不可用（`eventBusBridge.send()` 静默丢弃）：浏览器形态只能读（HTTP），不能驱动主循环。

运行时目录/配置事实：`Configs/default.json → server`：

```json
{ "host": "127.0.0.1", "allowRemoteAccess": false, "httpPort": 3000, "wsPort": 3001, "corsOrigins": ["http://localhost:5173"] }
```

## 2. HTTP 控制面约定

### 2.1 监听地址（bind policy）

- 默认只绑 **回环**（`DEFAULT_BIND_HOST = 127.0.0.1`）。
- 配了非回环地址但未显式 `server.allowRemoteAccess: true` → **回退回环并告警**（不静默改用户意图）。
- 非回环 + 显式允许 → 必须配置 `server.apiToken`（远程形态只有这一条凭据路径）。

来源：`Src/Interface/WebServer/bindPolicy.ts`。

### 2.2 本机控制面身份门（API Token）

- 头字段（二选一）：`x-civitas-api-token: <token>`（客户端用专用头）或 `Authorization: Bearer <token>`。
  - 专用头存在的原因：`Authorization` 留给治理侧的用户身份验真（`approvalApi` 用 Bearer 向账号服务验真），两个凭据语义不同，不能混用。
- 凭据来源：
  1. `server.apiToken`（配置显式提供，远程形态唯一路径）；
  2. 进程内随机生成（`randomBytes(32)`，**不落盘**）——桌面形态由主进程经 IPC 交给渲染进程。
- 领取通道：`POST /internal/api-token`（不在 `/api/*` 前缀内）
  - 仅**回环**开放；要求：`POST`、若带 `Origin` 必须是回环、服务端未开远程访问；
  - 响应不回显 CORS 头、`Cache-Control: no-store`；
  - 目的：浏览器开发态渲染进程自举拿凭据，同时防止任意跨站页面读取。
- **fail-closed**：未初始化 token 时 `/api/*` 一律 **401**（不存在"忘了装配 = 无鉴权"）。

来源：`Src/Interface/WebServer/apiToken.ts`。

### 2.3 响应包络

```ts
成功: { ok: true, data: unknown }          // 状态码默认 200（创建类为 201）
失败: { ok: false, error: string }          // 状态码由 handler 给出（400/404/409/500…）
```

来源：`Src/Interface/RestApi/router.ts` 的 `json()` / `apiError()`。

### 2.4 限流

- 配置：`Configs/supervision.json → supervision.apiRateLimit`
  - `maxRequestsPerMinute: 600`、`burstAllowance: 2` → 每 IP 有效上限 `600 × 2 = 1200 次/分`（固定 60s 窗口）。
- 维度：客户端 IP（可选 `x-forwarded-for`）。
- 响应头：无论是否限流都设置 `X-RateLimit-*`。
- 被限流：`429`，体为 `{ ok: false, error: "rate_limited", retryAfter: <秒> }` + `Retry-After`。

来源：`Src/Interface/WebServer/apiRateLimiter.ts`。

### 2.5 查询/路径参数约定

- 路径参数用 `:name` 记法（如 `/api/sessions/:sessionId/messages`）。
- 查询串解析为 `Record<string, string>`（同键重复取最后一个；不做类型转换，handler 自行 `parseInt`）。
- 未命中路由 → `404`；方法不匹配 → `404`（`matchRoute` 先按 method+path 精确匹配）。

## 4. 命令与事件通道（IPC 桥）

### 4.1 事件：`backend-event`（主进程 → 渲染进程）

- 桥接实现把 EventBus 的**全部** `EventType`（83 种）转发为 IPC 消息：

```ts
BridgeMessage = { type: string; data: unknown; timestamp: number }
```

- 渲染侧经 `Client/src/services/eventBusBridge.ts → subscribe(handler)` 订阅；`type` 取值为 §5 的事件名。
- 广播失败只记一次日志、绝不抛出（历史 bug：广播异常曾导致整条下行链路失效）。

### 4.2 命令：`backend-command`（渲染进程 → 主进程）

- 帧格式：`JSON.stringify({ type: string, payload?: Record<string, unknown> })`；非法帧静默忽略。
- **命令全集（7 种）**：

| `type` | 语义 | 关键 payload |
|---|---|---|
| `subscribe` | 订阅事件（按类型过滤） | 订阅参数 |
| `unsubscribe` | 退订 | 订阅标识 |
| `get_dashboard` | 取循环面板快照 | — |
| `get_approvals` | 取审批队列 | — |
| `generate_reply` | **发起一次生成**（驱动主循环） | 会话/模型/输入等 |
| `stop_generation` | 中止当前生成 | `traceId`/`loopId` |
| `ping` | 连通性探测 | — |

> 浏览器开发态：`eventBusBridge.send()` 直接丢弃命令并 `console.warn`（无命令通道），因此浏览器形态只能读不能写。

### 4.3 流式回复约定

生成过程不通过命令通道回传，而是**事件**：

- `agent:stream_chunk`（正文/思维链增量）
- `agent:iteration_complete`（单轮结束）
- `agent:tool_call_started` / `agent:tool_call_pending` / `agent:tool_call_result`（工具生命周期）
- `agent:stream_end`（含 `{ tokensUsed, exitReason }`）
- `chat:session_renamed`（**单独事件**：会话自动改名）

## 6. 事件持久化与回放（EventStore）

- `Src/Interface/EventStore/aiEventStore.ts`
  - `shouldPersist(type)`：只持久化"AI 组件需要重建"的事件子集；
  - `persistAiEvent(...)`：落 `ai_events`（`session_id` / `type` / `data_json` / `ts`）；
  - `listAiEvents(sessionId, { sinceTs, limit })`：按会话回放（HTTP：`GET /api/sessions/:id/ai-events`）；
  - `countAiEvents` / `clearSessionEvents` / `startAiEventPersistence` / `stopAiEventPersistence`。
- `Src/Interface/EventStore/traceIndex.ts`：从日志构建 trace 索引并写盘（`buildTraceIndex` / `writeTraceIndex`），供可观测页回溯。
- 回放契约：`ai-events` 返回 `{ events: [{ id, type, data, timestamp }], total }`；前端按 `type` 重放组件状态。

## 7. 输入去重（防风暴）

`Src/Interface/InputDeduplication/dedupMiddleware.ts` 实现 5 道防线（Phase 0–2 为进程内实现）：

1. **去重键**：`hash(source + intent + target)`，TTL 内重复 → 命中；
2. **冷却期**：按 agent 的最小间隔；
3. **幂等 ID**：同 `idempotencyId` 直接返回首次结果；
4. **并发上限**：按用户/agent 的并发计数；
5. **熔断**：连续失败/超限后短时熔断。

对外不新增 HTTP 端点；由调用链（IPC 命令 / Agent 入口）在**进入主循环前**使用。

## 8. 与桌面 IPC 的边界

- 桌面形态下，渲染进程**优先走 IPC**（51 通道，见客户端文档），HTTP 控制面主要服务浏览器开发态与主进程转发。
- IPC 通道与 HTTP 路由**不是一一映射**：IPC 是"按功能收口"的窄接口（如 `ipc-list-sessions`），HTTP 是"资源式"宽接口（`/api/sessions`）。
- 两套入口共用同一批 Services；新增能力时**两边都要登记**，避免"只有一边能观测"。
