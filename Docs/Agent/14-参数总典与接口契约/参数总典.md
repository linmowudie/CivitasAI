# 参数总典（开发速查）

> **本文定位**：全系统 **参数、单位、枚举、映射、契约** 的**唯一速查入口**。开发时先查本文定位"某个值在哪、叫什么、什么类型、谁消费"，再跳到对应事实源看完整上下文。
>
> **本文不是事实源**。所有数值以「定义位置」列指向的文件为准；本文与事实源冲突时，**以事实源为准并立即回修本文**。
>
> **上游四层事实源（SSOT）**：
>
> | 层 | 唯一事实源 | 管辖范围 |
> |----|-----------|---------|
> | 配置键 + 默认值 | `Docs/Agent/10 §1.1 / §2.1–§2.11` | 全部 `Configs/*.json` 的键名与默认值 |
> | DDL | `Docs/Agent/09 §1.1 / §2–§4 / §8.2` | 全部库表、列名、列类型、约束 |
> | 事件名 | `Docs/Agent/07 §4.3` | `EventType` 枚举全集（禁止自由字符串） |
> | 类型 schema 语义 | `Docs/Agent/11`（Loop）· `Docs/Agent/12`（Durable）· `Docs/Agent/02`（架构/契约） | 接口字段语义与判定规则 |
>
> **禁止行为**：在任何其他设计文档内联配置默认值、`CREATE TABLE`、或自写新事件字符串。

> **生效状态口径（2026-09-22 校准新增）**：§2 各参数表统一增列 **「生效」**，取值只有两个：
>
> | 标记 | 含义 |
> |------|------|
> | **✅ 运行期消费** | 键值经 `Configs/*.json → Infra/Config/configLoader.ts → Src/main.ts` 的 `getConfigValue*()` 注入运行期，**改 JSON 即生效** |
> | **⚠️ 未接线** | 改 JSON **不生效**。两种子情形：**a) 零引用** —— 键在 `Src/` 无任何字面量引用（纯设计态）；**b) 常量遮蔽** —— 运行期只用模块内 `DEFAULT_*` 常量或 `?? 字面量` 兜底，`Configs` 值从未注入（值当前与默认一致，故行为看不出差异） |
>
> **对账基数（2026-10-03 校准，替代 2026-09-22 的 204/104 口径）**：`Src/Infra/Config/configLoader.ts` 的 `loadConfig()` 实际加载 **12** 个 JSON（`default.json` + `extraConfigs` 11 个），合计 **254** 个叶子键（键路径口径；按叶名去重 219 个）。按「叶名在目标源码树内是否以字面量出现」的**宽松匹配**：约 **95 个叶名**（约 43%）在 `Src/` 零命中；放宽到 `Src + Client/src + Server/src` 后真零降至 **23 个叶名**。宽松匹配会**低估**死键数（`enabled`/`version`/`store` 等泛化名互相遮蔽），决定性键的判定以精确调用点 grep 复核为准。仍零消费的代表族：`verifier.*`、`context.*`（除两比例键）、`retention.*`、`supervision.* trigger/storm`、`durable.checkpoint/metrics/shutdown`、`reasoningSandwich.*`、`hardLimits.maxWallClockMsCeiling`。**2026-09-22 版所举 `hardLimits.*` 全族零引用已不成立**（见 §2.8(b) 校准注）。**2026-10-04 校准**：`verifier.minLevelsRequired` 与 `context.{outputReserveTokens,summaryTriggerUsageRatio}` 已接线（见 §2.8(e)/(f) 校准注），自此族中移除。
>
> **根因一句话（2026-10-03 校准）**：`getConfigValueOr()` 的调用点仍**只存在于 `Src/main.ts` 的 `startServer()`**——但已由 13 处增至 **18 处**（新增 `loopDefaults`/`hardLimits`/`stopRules`/`roleOverrides`/`supervision.rateLimit+apiRateLimit`/`durable.effect.writeSynchronous`/`security.autoApprove+approvalTimeoutSec`/`tools` 等直读，逐项见 §2 各行）；其余模块仍各自持有 `DEFAULT_*` 字面量——这是 §2 剩余 ⚠️ 的主要来源。另有**第二配置读通道**绕过 loader+validator：`Src/Interface/RestApi/configApi.ts` 的 `listConfigs()/getConfig()` 直接 `readFileSync` 读取 `Configs/*.json`（§5.4 风险项登记）。目标态（Docs/Agent/10 登记的键全集）**全部保留**，仅加状态标注。

## 0. 五层参数地图（自底向上）

按此顺序实现与查参，**下层不得依赖上层参数**（对齐 skill 五层单向依赖）。

| 层 | 目录 | 参数域 | 主要事实源 | 本文档节 |
|----|------|--------|-----------|---------|
| **L1 Infra** | `Infra/` | 数据库、LLM Provider、文件、配置加载、持久执行 | Docs/Agent/09、Docs/Agent/10 §2.1/§2.2/§2.9、Docs/Agent/12 | §2.1 §2.2 §2.3 §2.9 §3 |
| **L2 Tools** | `Tools/` | 工具契约（dangerLevel / idempotency / reversibility / 沙箱 / 限流） | Docs/Agent/10 §6 | §4.1 §4.6 |
| **L3 Services** | `Services/` | 上下文装配、共享记忆、Token 经济、仲裁、审计、监管 | Docs/Agent/07、Docs/Agent/10 §2.4–§2.7/§2.11、Docs/Agent/04–§06 | §2.4 §2.5 §2.6 §2.7 §2.11 |
| **L4 Core** | `Core/` | 主循环、StopRules、Verifier、LoopState、编排路由 | Docs/Agent/11、Docs/Agent/02、Docs/Agent/03、Docs/Agent/10 §2.3/§2.8 | §2.3 §2.8 §4 §5 |
| **L5 Interface** | `Client/`、`Interface/` | 服务端口、WS 协议、推送节流、审批面板 | Docs/Agent/08、Docs/Client/01、Docs/Agent/10 §2.1 | §2.1(ui) §4.5 |

**跨层红线（三条）**：
1. **单位/标度不得跨层变形**：比例只在 L5 展示层 ×100，其余层恒 0.0–1.0；时间戳全链路 epoch ms。
2. **参数不得跨层复制**：L3–L5 需要 L1 的值时**引用配置键名**，不写数值。
3. **ID 语义不得跨层混用**：`session_key` / `trace_id` / `operation_id` / `loop_id` 粒度固定（§6）。

## 1. 命名与单位规范

### 1.1 六条强制规则

| # | 对象 | 规则 | 正例 | 反例（v2.1 已清） |
|---|------|------|------|------------------|
| N1 | 配置文件键 | **camelCase** | `httpPort`、`qualityThreshold` | `max_consecutive_failures` |
| N2 | DB 表名/列名 | **snake_case**，与 TS 字段**机械转换** | `budget_used_tokens` | `timeoutMs` 对应列写成 `t_out` |
| N3 | TS 接口字段 | **camelCase**（`LoopConfig` 除外，见 X2） | `budgetUsedTokens` | — |
| N4 | 时长 | 键名**必带单位后缀**，数值不带单位 | `busyTimeoutMs: 5000`、`approvalTimeoutSec: 60`、`loopConsecutiveRounds: 5` | `timeout: 5000`、`monitoringInterval: "60s"` |
| N5 | 比例 / 评分 | 一律 **0.0–1.0** 浮点；DB 列 `REAL` | `qualityScore: 0.85` | `quality_score INTEGER /* 0-100 */` |
| N6 | 时间戳 | TS `number`（**epoch 毫秒**）+ `_at` 后缀；DB 列一律 `INTEGER` | `recordedAt` / `recorded_at` | ISO-8601 `TEXT` |

其他后缀：金额 `_usd`（REAL）· JSON 列 `_json` 结尾 · 布尔列 `is_*` / `*_enabled`（INTEGER 0/1）· 计数 `*Count` · 上限 `*Ceiling` · 倍率 `*Multiplier` / `*Factor`。
