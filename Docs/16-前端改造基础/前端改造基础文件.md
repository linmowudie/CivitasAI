## 1. 需求溯源：系统对前端的要求

### 1.1 来自 PRD（产品需求文档：Civitas-AI）

PRD §4.2 可观测性要求提供**全局"城邦大屏"**，实时展示：Token 流向、Agent 活跃状态、当前正在进行的仲裁案件。PRD §2 定义了 7 类系统角色（Prime Director / Partner / Worker / Assembly Line / 仲裁庭 / 监管局 / 资源审计局），前端需能区分并呈现这些角色的行为轨迹。

### 1.2 来自 Docs/09《用户界面与可观测性设计》

- **布局**：顶部导航（系统名/当前任务/全局 Token 余额）+ 左侧导航 + 主内容区 + 底部实时事件流 + 底部状态栏（系统状态/活跃 Agent 数/当前税率）。
- **五大视图**：城邦大屏（状态卡片、力导向拓扑图、Token 桑基图、甘特时间线、仲裁卡片、告警列表）、任务面板、Agent 监控、Token 账本、仲裁视图，另有系统配置。
- **实时通信硬约束**（SSOT 裁决，前端不得自接新事件字符串）：
  - 流式输出走 WS `agent:stream_chunk`（旧文档写法 `stream_chunk` 已归入 Docs/07 §4.3 废弃表），按 `ui.streamFlushIntervalMs`（默认 100ms）批量合并，**禁止逐 token 推送**；
  - WS 断线重连：退避基数 `ui.wsReconnectBackoffMs`，最多 `ui.wsReconnectMaxAttempts` 次，耗尽后**降级为纯轮询并显示离线横幅**；
  - 本地事件缓冲上限 `ui.maxEventBufferSize`，超限丢最旧；
  - 百分比展示 ×100，内部存储 0.0–1.0。
- **技术选型约束**：React 18+ / Vite / Zustand / ECharts(主)+D3(辅) / Ant Design / 原生 WebSocket / axios。
- **可视化红线**：每个可视化元素必须解释实际问题或支持决策，禁止无实质价值的图表。
- **Phase 规划**：P1 = 任务提交 + 流式输出 + 基础 Agent 列表；P2 = Token 账本 + 仲裁视图 + Agent 详情；P3 = 城邦大屏全量 + 系统配置。

### 1.3 来自 S13 后端接口契约（必须对齐）

S13 已交付 REST API（`router.ts` + taskApi/agentApi/tokenApi/approvalApi/loopApi）与 WebSocket 模块（`wsServer.ts`/`wsHandler.ts`）。

> ⚠️ **重要修正（逐行核查后）**：上述交付是**函数级契约，不是可访问的网络服务**——`webServer.ts` 自陈"Phase 0-2：内存请求模拟（不绑定端口）"，`wsServer.ts` 为内存事件桥，全 `Src/` grep `createServer|listen(` 0 命中，且 `main.ts` 启动到 ⑱ 就止、从未调用 `registerAllRoutes()`。因此"前端未消费契约"只是表象，根因是**契约尚未成为网络端点**，详见方案文件 §1。

> **2026-09-22 校准（时点标注）**：上段为 **F0 前**诊断，保留原文以留痕 F0 的立论依据。该根因已由 F0.1–F0.3 消除：`WebServer/httpServer.ts:52,89` 起 `http.createServer` 并 `listen(3000)`、`WebSocket/wsGateway.ts:37` 起 WS 网关 `listen(3001)`、`main.ts:252-263` 依次调用 `registerAllRoutes()` → `startHttpServer()` → `startWsGateway()`；`webServer.ts` 仅保留给单测。

## 3. 业界调研：AI 前端界面必备要素与大厂范式

### 3.1 通用 AI 对话界面的"九大区域"（业界共识，源自 ChatGPT/Claude/Perplexity/Cursor 的解剖）

1. **会话历史侧边栏**：跨会话持久化，可搜索/重命名/归档（ChatGPT 左侧栏、Claude Projects 分组）。
2. **对话流主区**：消息列最大宽度 65–80 字符/行（ChatGPT/Claude 均 ~768px）；扁平全宽消息取代 SMS 式圆气泡。
3. **用户消息**：右对齐/视觉区分，**可编辑**，编辑后显式选择"分叉或替换"后续对话。
4. **助手消息**：富 Markdown 渲染（标题/列表/表格/公式/图表），**每条消息标注产出模型名**。
5. **输入区**：多行 textarea，Enter 发送 / Shift+Enter 换行，随内容增长、封顶后内部滚动；附件按钮 + 模型选择器 + 快捷提示。
6. **停止/重新生成**：流式期间必须有醒目 Stop 按钮（可省 API 成本）；结束后出现 Regenerate；**中断后保留已生成部分并提供"继续"**。
7. **单消息操作**：复制（代码块一键复制 + 瞬时对勾）、点赞/点踩、编辑、分享、从此处分叉；桌面 hover 显示、移动端常显。
8. **流式渲染**：首 token 800ms 内出现，否则显示排队态；**缓冲不完整 Markdown 防抖动**（Vercel Streamdown 专门解决此问题）；代码块等 closing fence 再渲染。
9. **后续建议 chips**：可关闭，仅在探索型场景启用。

### 3.2 状态与信任设计（生产级与 Demo 的分界线）

- 消息六态：queued → streaming → complete → error → stopped → regenerating，每态有明确视觉。
- 错误必须**指明类别**（限流/内容过滤/网络）与恢复动作，禁止笼统 toast。
- 自动滚动尊重用户：距底部 <100px 才跟随，用户上滑即锁定。
- 引用/溯源：检索增强回复必须展示来源。
- 上下文诚实：接近上下文窗口时提示"较早消息已摘要"，禁止静默截断。
- 无障碍：`aria-live="polite"` 播报流式内容、全键盘路径、WCAG AA 对比度、尊重 `prefers-reduced-motion`。

### 3.3 大厂实现范式速览

| 产品 | 关键范式 | 可借鉴点 |
|------|---------|---------|
| ChatGPT | 极简三栏（历史/对话/输入）；Canvas 分屏编辑；记忆系统（可查看/编辑/删除） | 消息上单条标注模型；分屏工作区 |
| Claude | Artifacts 分屏范式（对话 + 实时预览面板、版本控制、公开 URL）；Projects 项目级记忆；网页化排版（表格/文件卡片/代码模块分层） | **Artifact 卡片**模式极适合展示 Agent 产出物；"对话即工作台" |
| Gemini | 多模态集成、1M 上下文、与 Google 生态嵌入 | 长上下文的摘要提示交互 |
| Cursor/Cline | 领域化单消息操作（"Apply to file"）；diff 展示 | 工具调用结果的领域化渲染 |
| DeepSeek | 链式思考（CoT）过程展示、DeepThink/联网开关 | **思考过程可视化**开关 |
| Vercel AI SDK | `useChat` hook 标准化流式状态机；Streamdown 流式 Markdown | 前端流式状态管理的标准实现路径 |
| LangSmith/Langfuse | Agent 追踪 UI：执行时间线（模型→工具→模型）、每 span 的输入输出/Token/延迟/错误、图视图 + 交互式回放 | TraceReplay 视图的业界标准形态 |
| CopilotKit / assistant-ui / OpenAI Agents SDK | HITL（human-in-the-loop）作为运行态一等公民：运行可序列化暂停、审批结果写回上下文；工具调用卡片（参数/结果可展开） | ApprovalQueue 应与 Loop 状态联动而非孤立列表 |

### 3.4 对 Civitas-AI 的特殊性要求（Agent 城邦 ≠ 通用聊天）

除通用聊天要素外，本项目前端还承担**多 Agent 系统驾驶舱**职责，业界对应 LangSmith/AgentOps 类产品：
- **推理流程图**：决策点、工具选择、分支回溯的语义化调用栈；
- **状态时间线**：任意时刻 Agent 知道什么、想做什么（Loop 十步序列可视化）；
- **Token 经济可视化**：桑基图（系统池→钱包→消耗/税/分润）——这是本项目的差异化卖点，业界无现成品；
- **HITL 审批**：审批卡片需内嵌上下文（风险等级、payload、请求方、双角色要求、超时行为），批准/拒绝结果回流到 Loop。

## 5. 验收基准（改造完成的判据）

1. 断开后端 → 前端显示离线横幅并自动降级轮询；恢复后自动重连（≤5 次退避）。
2. 真实 Agent 调用时消息流式渲染，期间 Stop 可用，中断后保留部分输出并可"继续"。
3. 任一助手消息可见产出模型名与 Token 消耗；代码块一键复制。
4. 审批队列展示真实 PendingApproval，批准/拒绝写回后端并被 Loop 感知。
5. 大屏桑基图/拓扑图数据来自真实 EventBus 事件，且每个图表能回答"它解释了什么问题"（Docs/09 红线）。
