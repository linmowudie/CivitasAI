# Civitas-AI 前端改造方案与构建顺序

> 依据：[前端改造基础文件.md](./前端改造基础文件.md)。本文件给出**决策完备**的改造方案与严格分阶段的构建顺序（F0–F6），每阶段含产出清单与 Gate 判据，未过不得进入下一阶段。风格与 S0–S14 一致。

## 1. 前提修正：真正的阻塞点在后端，不在前端

基础文件判定"前端零对接"。经对 `Src/Interface` 与 `Src/main.ts` 逐行核查，事实比"未对接"更严重：

| 发现 | 证据 | 影响 |
|------|------|------|
| **没有真实 HTTP 服务** | `WebServer/webServer.ts` 注释即"Phase 0-2：内存请求模拟（不绑定端口）"；全 `Src/` grep `createServer\|listen(` **0 命中** | 前端无处可调，`api.ts` 无法实现 |
| **没有真实 WebSocket 服务** | `wsServer.ts` 注释"内存事件桥（不依赖真实 WS 库）"，用 `connectClient()`/`consumeMessages()` 函数模拟收发 | 流式输出与实时推送全部落空 |
| **main.ts 从未启动接口层** | 启动跑到 ⑱ AgentRuntime 就止于"Awaiting next startup step"，无 `registerAllRoutes()`、无 `initWsServer()` | 服务即使写了也没被装配 |
| **审批无决策端点** | `approvalApi.ts` 只有 2 个 GET；`approvalGate.decideApproval()` 未暴露 | HITL 审批只能看不能批 |
| **任务不触发执行** | `taskApi.submitTask()` 只写内存 Map；`orchestrator.receiveTask()` 存在但无人调用 | 提交任务后系统什么都不做 |
| **`stream_chunk` 事件不存在** | `eventTypes.ts` 40+ 枚举中无流式事件，而 Docs/09 §3.2 要求前端订阅 `stream_chunk` | SSOT 冲突，前端按文档接必失败 |
| **无对话会话 API** | `Services/Session/sessionManager.ts` 有 createSession/getActiveSessions，但无 REST/WS 暴露，且无消息历史存储 | ChatView 无后端可依 |
| **契约文档与代码路径已偏离** | Docs/08 §5.2 写 `/api/dashboard/overview`、`/api/arbitration/cases`，代码实为 `/api/loops/dashboard`、`/api/loops/arbitration`；Docs/08 §5.1 客户端帧 `submit_task` 等 5 值与代码 `subscribe/get_dashboard` 完全不同 | 按文档写前端必 404；需附录 A 定权威映射 |

**结论**：改造必须 **F0 先补传输层与契约缺口**，前端阶段（F1 起）才有地基。任何"先做前端 UI"的尝试都会退化为第二套 mock。

> **文档同步状态（2026-09-14）**：本文件的裁决已回写设计文档——Docs/07 §4.3（新增 3 个 `agent:` 域事件 + 废弃 `stream_chunk` 旧名）、Docs/09 §3.2/§4/§5/§7（事件名、选型、目录差异、Phase 现状）、Docs/11 §5（`ws` 依赖登记）。本文件与上述四处的数值/事件名以 SSOT 为准，不再单独维护。

## 2. 目标架构

```
后端  Interface/RestApi  ←─ HTTP :3000 ─→  services/api.ts (原生 fetch)
      Interface/WebSocket ←─ WS   :3001 ─→  services/ws.ts   (原生 WebSocket)
                                                   ↓ 事件名严格取自 eventTypes.ts
                                             stores/* (Zustand)  ← 唯一状态源
                                                   ↓
                                             hooks/* (useWebSocket / useTaskStream / useDashboardData)
                                                   ↓
                                             views/* → components/*（纯展示，不直连网络）
```

铁律：
1. **视图层禁止出现 `fetch`/`new WebSocket`**，一律经 `services/` → `stores/`；
2. **前端不得自定义事件字符串**，事件名从后端 `eventTypes.ts` 生成 `Client/src/shared/eventTypes.ts`（F0.6 产出，构建期脚本同步）；
3. 展示百分比 ×100，内部 0.0–1.0；UI 参数一律读 `Configs/default.json → ui.*`，禁止硬编码数值。

## 3. 技术选型裁决（需回写 Docs/09）

| 项 | Docs/09 原定 | 裁决 | 理由 |
|----|-------------|------|------|
| UI 组件库 | Ant Design | **不引入**，继续 Tailwind 4 + 自绘组件 | 现有 `index.css`(15KB) 已成型一套暗色驾驶舱设计语言，8 视图全部基于它；引 antd 会双轨打架。Docs/09 §4 该行修订 |
| 可视化 | ECharts + D3 | **引入 ECharts 5**（`echarts` + `echarts-for-react`），D3 仅在力导向图需要自定义布局时补 | 桑基/甘特/关系图 ECharts 原生支持；同时移除已装未用的 recharts |
| 状态管理 | Zustand | **引入 Zustand 4** | 与铁律 2 配套，跨视图共享 Agent/Loop/Token 状态 |
| WS 服务端 | 未定 | **新增 `ws` 依赖**（仅后端 runtime） | 手写 RFC6455 成本与风险远高于引一个成熟小包；前端仍用浏览器原生 WebSocket。已登记 Docs/11 §5 |
| HTTP 客户端 | axios | **改为原生 `fetch`** | 前端无拦截器需求，少一个依赖；Docs/09 §4 该行修订 |

**Gate G0**：`npm run dev:server` 后 `curl :3000/api/agents` 返回真实 JSON；`wscat -p 3001` 收到 `loop:started`；`POST /api/approvals/x/decide` 能改变 `getApproval().status`；`DELETE /api/tasks/x` 可使 Loop 转入中止；**附录 A 中每一条路径均能 `curl` 通**；既有 582 项测试零回归。

### F2 · 对话可用（对齐基础文件 P0 全部项）

产出：`views/ChatView.tsx` 重构 + `components/Chat/{MessageList,MessageBubble,Composer,StreamingIndicator,MessageActions}.tsx`
- 流式：订阅 `agent:stream_chunk`（收尾 `agent:stream_end`），按 `streamFlushIntervalMs`(100ms) 合批渲染，**禁止逐 token setState**；
- Markdown：引入 `react-markdown` + `shiki` 代码高亮，**未闭合代码块缓冲**（防抖/防闪烁，参照 Streamdown 思路）；
- 消息六态：queued/streaming/complete/error/stopped/regenerating 全建模；
- 控件：**Stop（流式中常显）/ Regenerate / 编辑重发（显式分叉或替换）/ 复制 / 赞踩 / 导出为图片**；

- 滚动：距底 <100px 才自动跟随，用户上滑即锁定；

**Gate G2**：真实提交一句任务，首字 ≤ 800ms 内出现（否则显示排队态）；流式中点 Stop 保留已输出部分并可"继续"；代码块一键复制成功；刷新页面会话不丢。

### F3 · HITL 审批闭环

产出：`views/ApprovalQueue.tsx` 重构 + `components/Approval/ApprovalCard.tsx`
- 数据源 `GET /api/approvals`，新审批靠 `loop:approval_requested` 推送（`ui.approvalQueueRefreshSec` 兜底轮询）；

- 超时前端不做假递减到 0，一律显示后端 `approval_timeout_rejected` 为准。

**Gate G3**：真实触发一次审批门 → 点批准 → 后端 Loop 继续推进（trace 可见）；拒绝路径同上；CRITICAL 单角色批准必须被后端拒绝并在 UI 明示。

### F4 · 城邦大屏可视化

## 5. 禁止抢跑规则

1. **G0 未过，禁止开始 F1**——否则只是给另一套 mock 换皮；
2. F1 完成前，任何视图不得引入新图表（先有真数据，再谈可视化）；
3. F2 的流式实现不得用 `setTimeout` 或假延迟兜底；
4. 事件名只允许来自 `src/shared/eventTypes.ts`，`views/` 出现裸字符串事件名视为违规；
5. 五层单向依赖红线同样适用于前端：`views → hooks → stores → services`，禁止反向与跨层直连。
